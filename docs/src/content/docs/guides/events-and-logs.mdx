# Scope: choosing which events to receive, handling them, and capturing logs.
---

Events tell you what happens in a map as it runs, like a style finishing loading
or a tile failing to load. This guide shows how to receive map events and the
library's logs.

## Set an event handler

Events come from the runtime, so one event handler, set with
[](api:mln_runtime_set_event_handler), receives the events of the runtime and
all its maps. Set it before you create a map, so it receives the map's first
events.

Each event names its type and the map that sent it. The handler runs on a
library thread, so hand longer work to another thread.

<Snippet page="events-and-logs" region="handler" />

## Filter events

By default, a map sends every event. To get only the events you act on, set
[](api:mln_map_options.event_mask) when you create the map, or change it later
with [](api:mln_map_set_event_mask). Events cover style and resource loading,
rendering, and camera changes, and [](api:mln_runtime_event_type) lists them
all.

<Snippet page="events-and-logs" region="mask" />

## Capture logs

To send the library's logs to your logger, set a log callback with
[](api:mln_log_set_callback). One callback receives the logs of every runtime in
the process.
