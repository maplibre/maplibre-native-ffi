Two extension points intercept the network requests that a map makes. A resource
transform rewrites a URL before the request is sent, and a resource provider
answers the request with bytes that you supply. Register either one on the
runtime, from the runtime owner thread.

Every value that a callback reads must be safe to read from several threads at
once, because MapLibre may invoke either callback on a network or worker thread
instead of the runtime owner thread. Return from each callback quickly, because
the resource request waits for it. A transform callback calls one function, which sets the replacement URL on the response. A provider callback calls
the request handle functions, and only for the handle that it received.

## Rewrite a URL with a transform

Rewrite the URL when a request needs a credential, a signature, or a different
host. The transform runs for every resource that MapLibre fetches over the
network, including nested PMTiles range requests. Resources that MapLibre loads
from files, assets, MBTiles archives, and the cache database reach the map
without the transform.

Compare the URL against your own host before you attach a credential, because a
style names glyphs, sprites, and tiles on origins that you do not control.

## Serve the bytes with a provider

Supply the bytes yourself when MapLibre cannot load a resource on its own, such
as an archive inside your application package or a scheme of your own. Such a
scheme reaches the provider, because MapLibre routes every scheme that it does
not recognize to the network layer. A request that the provider handles never
reaches the transform, because the provider runs before MapLibre's online file
source.

Match the requests that your host serves, and pass every other request through
to MapLibre's network stack. Fetch the resolved URL, which includes the tile
server normalization and the API key that the runtime applies. The requested URL is the logical identity that the cache stores.

A provider that owns an I/O pool reports the same decision, keeps the handle, and completes the request from any thread once the bytes arrive. Check
whether the request was cancelled before expensive work, because MapLibre
cancels requests whose resources it no longer needs. Release each handle exactly
once, after you complete the request or decide against completing it.

## Keep callback state reachable

The runtime stores each callback and its user data by reference. Keep any host
state that a callback reads reachable until you register a replacement, clear
the callback, or destroy the runtime. Each of those calls waits for in-flight
callbacks to return. Free that state after one of those calls returns. Release
any host lock that a callback also acquires before you destroy the runtime, because a callback blocked on that lock cannot return,
and neither can the destroy call.
