Choose a resource transform to rewrite URLs, an HTTP header transform to add
headers, or a resource provider to supply response bytes from host storage.
Register each configuration on the runtime.

Callbacks can run concurrently on native threads, so protect shared state and
return quickly.

## Rewrite a URL

Use a transform to sign a URL or select another host. Check the destination
before you add credentials, because styles can request tiles, sprites, and
glyphs from origins that the host does not control.

<Code code={region(transformSnippet, "match")} lang="c" title="resource-transform.c" />

Complete the request with the replacement URL, then release it. A host can also
answer later, from any thread.

<Code code={region(transformSnippet, "rewrite")} lang="c" title="resource-transform.c" />

Register the transform before you load resources that need it.

<Code code={region(transformSnippet, "install")} lang="c" title="resource-transform.c" />

## Add HTTP headers

Use a header transform for credentials that belong in headers, and check the
transformed origin before you return them. A host that cannot run code on
MapLibre threads supplies a table of header rules instead of a callback.

Set the header names and values.

<Code code={region(headerSnippet, "set")} lang="c" title="http-header-transform.c" />

Register the transform, and clear or replace it when credentials change.

<Code code={region(headerSnippet, "install")} lang="c" title="http-header-transform.c" />

### Platform support

Header transforms are unavailable on OpenHarmony and in the browser. Use a
provider there.

The [runtime reference](/maplibre-native-ffi/reference/c/runtime_8h.html)
covers redirect handling and the request paths that bypass transforms.

## Supply response bytes

Use a provider for host-managed storage or a custom URL scheme. Match requests
that the host serves, and pass the others to MapLibre's network stack.

When bytes are already available, complete and release the request in the
callback.
