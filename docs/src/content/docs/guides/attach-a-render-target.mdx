A render session draws one map into one render target, and a map carries at most
one live session. A map is useful before any session exists: it loads a style,
accepts sources and layers, and holds a camera, and it keeps all of that when a
session is attached or released.

Attaching needs a live map, and the attaching thread becomes the session's owner
thread for as long as the session lives. A host therefore attaches on the thread
that owns its graphics context and will draw the frames, even when the runtime
and the map are pumped on another thread.

## Choose the kind of target

A native surface draws to a window or a view and presents each frame to it. Your
host creates the window, the graphics context, and the surface, and the session
presents into that surface rather than leaving the swap to you. Choose it for a
map on screen.

A session-owned texture draws offscreen into a texture that the session
allocates. Choose it when there is no window, such as an image service or a
thumbnail job, or when you composite the map into a scene and have no texture of
your own to supply. Your host samples the last frame on the GPU by acquiring it
and releasing it when it has finished reading, or copies the frame into host
memory, which
[Render a Static Image](/maplibre-native-ffi/guides/render-a-static-image/)
covers alongside the static map mode that produces one image per request.

A borrowed texture draws offscreen into a texture that your host allocated and
owns, such as a material in a 3D scene, a frame from a compositor's pool, or an
image from an XR swapchain. Your host controls the format and the lifetime and
copies out with the graphics API that created the texture. Choose it when the
destination already exists.

A borrowed target additionally states the texture's physical size in device
pixels, separately from the logical extent, and names the texture itself. The

## Resize, replace, and release

A window resize is the common case, and it needs neither a new target nor a new
session. Surface and session-owned texture targets resize in place, on the
session's owner thread.

<Code code={region(renderTarget, "resize")} lang="c" title="render-target.c" />

A borrowed texture is the exception, because its size is the size of the texture
your host allocated. Resizing reports an unsupported status, and the way to
change the size is to allocate a new texture and supply it as a replacement
target, below.

A host surface can be destroyed and recreated while the map lives on, which is
what an Android rotation, a Flutter surface lifecycle change, and a
resize that reallocates all look like from here. Replacing the target in place
keeps the session and its renderer, so loaded tiles and feature state survive
the change. Borrowed texture targets replace the same way, when your host
allocates a new texture.

<Code code={region(renderTarget, "set-target")} lang="c" title="render-target.c" />

A change to the scale factor is the exception. A renderer compiles its shaders
for a fixed pixel ratio, so that change builds a new renderer, and feature state
starts empty on it.

Release the session before the map. Destroying a map while a session is attached
reports an invalid-state status.

That ordering crosses threads when the session and the map have different owner
threads. The thread that owns the map cannot release the session, so it waits
for the thread that attached it, and a bound on that wait keeps a thread that
has already failed from hanging the teardown.
