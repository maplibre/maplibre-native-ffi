A render session draws one map into one target. Choose a native surface for a
window or view, an owned texture target for offscreen rendering, or a borrowed
texture target for compositing into host textures. Map state remains available
after the session detaches.

## Choose graphics execution

A core-worker driver runs graphics work on a native thread. A
caller-graphics-thread driver requires service on the host's graphics thread.
Metal and Vulkan support either driver. WebGPU requires the caller driver.

### OpenGL targets

Existing EGL, WGL, and WebGL contexts use the caller driver. A private EGL or
WGL owned texture target and a transferred `OffscreenCanvas` use a core worker.

### Shared Vulkan queues

Pass a queue lock when the host and the session submit to the same Vulkan queue.
When the host's lock is native code, pass its lock and unlock functions as a
native registration, so that the session calls them without entering the
binding's language runtime. Dart and TypeScript accept only that form. Rust,
Swift, and Zig have none, because their callbacks can call a native lock
directly. The
[target reference](/maplibre-native-ffi/reference/c/render__target_8h.html)
states the rules for contexts and queue locks.

## Attach the target

Provide the graphics context and extent in the backend descriptor, and install
wakes that schedule frame-result drains and caller-driver service on the host.
Attachment completes asynchronously; keep servicing a caller driver until it
does.
