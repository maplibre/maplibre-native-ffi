A surface render session renders a map into a host-provided native surface and
presents through it. This is the integration for windows, views, and platform
surfaces: the host owns the window toolkit and the graphics context, and the
session draws into them.

## The surface contract

A map has at most one live render session. You create a session by attaching a
surface descriptor to the map with a backend-specific attach function; the
backend is fixed by the native artifact you installed. All session calls run on
the map owner thread.

The surface handle the descriptor carries depends on the backend:

| Backend      | Descriptor field | Actual type                | Presented by     |
| ------------ | ---------------- | -------------------------- | ---------------- |
| Metal        | `layer`          | `CAMetalLayer*` (retained) | Layer drawable   |
| Vulkan       | `surface`        | `VkSurfaceKHR`             | Swapchain        |
| OpenGL (EGL) | `surface`        | `EGLSurface`               | `eglSwapBuffers` |
| OpenGL (WGL) | `surface`        | `HDC`                      | `SwapBuffers`    |

The API works with these ready-made handles rather than toolkit objects, so the
host creates them first: on Android, wrap an `ANativeWindow*` in an
`EGLSurface` or a `VkSurfaceKHR`; on Linux, create an `EGLSurface` or
`VkSurfaceKHR` from your X11/Wayland window; on Windows, use the window's
`HDC`; on Apple platforms, hand over the view's `CAMetalLayer`.

The descriptor also carries a **context** — the backend objects the session
shares with your application (Metal device; Vulkan instance, device, and
graphics queue; an EGL or WGL share context). The descriptor's extent is the
logical viewport size in UI pixels plus the UI-to-device scale factor.

## Drive the frame loop

Rendering is pull-based and host-paced. Each frame:

1. Pump the runtime (`run_once`) and drain events.
2. When `MLN_RUNTIME_EVENT_MAP_RENDER_UPDATE_AVAILABLE` arrives for your map,
   mark rendering as pending.
3. When pending, call `mln_render_session_render_update()`. Surface sessions
   render **and present** in this call. The call reports whether it produced a
   frame; `false` at startup is normal (the map has not published an update
   yet) — keep pumping and retry.

`MAP_RENDER_FRAME_FINISHED` events carry a `needs_repaint` flag; keep rendering
while it is set to let animations and symbol placement settle.

Pace the loop with the display where you can: vsync callbacks
(`CADisplayLink`, Android's `Choreographer`), or your toolkit's frame callback.
The example apps poll with a short sleep, which is simplest but burns cycles.

    // Attach: layer is a CAMetalLayer*, VkSurfaceKHR, EGLSurface, or HDC
    // obtained from the host window toolkit.
    mln_opengl_surface_descriptor desc = mln_opengl_surface_descriptor_default();
    desc.extent = (mln_render_target_extent){
        .size = sizeof(mln_render_target_extent),

    };
    desc.context.data.egl.display = egl_display;      // borrowed
    desc.context.data.egl.config = egl_config;        // borrowed
    desc.context.data.egl.share_context = egl_ctx;    // borrowed
    desc.context.platform = MLN_OPENGL_CONTEXT_PLATFORM_EGL;
    desc.surface = egl_surface;                       // borrowed

    mln_render_session* session = NULL;
    mln_opengl_surface_attach(map, &desc, &session);
    bool pending = false;

    // Per frame, on the map owner thread:
    mln_runtime_run_once(runtime);
    mln_runtime_event event = {.size = sizeof(event)};
    bool has_event = false;
    while (mln_runtime_poll_event(runtime, &event, &has_event) == MLN_STATUS_OK &&
           has_event) {
      if (event.source != map) continue;
      if (event.type == MLN_RUNTIME_EVENT_MAP_RENDER_UPDATE_AVAILABLE) {
        pending = true;
      } else if (
          event.type == MLN_RUNTIME_EVENT_MAP_RENDER_FRAME_FINISHED &&
          event.payload_type == MLN_RUNTIME_EVENT_PAYLOAD_RENDER_FRAME &&
          event.payload_size >= sizeof(mln_runtime_event_render_frame) &&
          ((const mln_runtime_event_render_frame*)event.payload)->needs_repaint) {
        pending = true;
      }
    }
    if (pending) {
      bool rendered = false;
      mln_render_session_render_update(session, &rendered);
      pending = !rendered;
    }

## Resize with the host surface

When the window changes size, call `mln_render_session_resize()` with the new
logical size and scale factor, then request a repaint. Resize rebuilds the
renderer on the next render update; map state (camera, style, sources)
survives, but renderer-held state such as feature state does not.

A scale factor differing from the map's original `scale_factor` logs a warning —
plan the map's scale factor around the displays you target.

## Follow the surface lifecycle

The session borrows the surface handle and context objects; they must stay
valid until detach or destroy. When the platform destroys the surface (window
closed, Android `surfaceDestroyed`, view detached):

1. Call `mln_render_session_detach()` to release the map slot, then destroy the
   old handle, or call `mln_render_session_destroy()` directly. A detached
   handle remains live only for destruction; it cannot render or be reattached.
2. Release the host surface and context.
3. When a new surface arrives, attach a fresh session — the same map continues
   with its camera and style intact.

<Aside type="tip">
  On Android, call `MaplibreAndroid.initialize(context)` once before any
  network activity, create the session from `surfaceCreated`/`surfaceChanged`,
  destroy it from `surfaceDestroyed`, and pace the loop with `Choreographer`.
  The `android-map` example shows the full pattern.
</Aside>

The full working versions of these loops, for every backend, live in the
example apps: `zig-map`, `rust-map`, `lwjgl-map`, `swift-map`, `dotnet-map`,
and `android-map`.
