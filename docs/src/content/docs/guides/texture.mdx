This guide shows how to render a continuous map into textures for another
renderer to draw, such as a UI framework, a game engine, or a compositor. It
builds on the frame loop from
[Render to a window](/maplibre-native-ffi/guides/window/#render-frames).

To read a map's pixels on the CPU instead, render offscreen, as in
[Render images](/maplibre-native-ffi/guides/images/).

## Attach a texture ring

The session renders into a ring of textures that you create on your GPU device,
so your renderer can draw one frame while the session renders the next. Create
two textures at the map's size in device pixels, which is its logical size times
its scale factor.

<Aside type="note">
  The snippets below use Vulkan. For another backend, use that backend's calls
  to attach and replace the texture ring, and to get each frame's texture. The
  other steps are the same.
</Aside>

On Vulkan, you can have the library create the device with
[](api:mln_vulkan_device_create), and create your textures on the context from
[](api:mln_vulkan_device_get_context). To share the textures with another
graphics API on the same GPU, name that GPU by its UUID or LUID in the options.
If your renderer submits to the same queue as the session, pass a lock in the
attach options, and hold it around your own submissions.

As with a window, use your graphics thread as the driver for OpenGL and WebGPU
textures, and the library thread otherwise. See
[Service driver work](/maplibre-native-ffi/guides/window/#service-driver-work).

<Snippet page="texture" region="attach-options" />

Then attach your textures, with your graphics context, such as your device and
queue, and the textures' size in device pixels. Keep the textures alive until
you replace them, or until the session detaches.

<Snippet page="texture" region="attach-borrowed" />

### Android hardware buffers

On Android 8.0 and later, the library can allocate the ring itself, as hardware
buffers that your UI draws, such as through `Bitmap.wrapHardwareBuffer`. Attach
with [](api:mln_map_attach_android_hardware_buffer_ring) and the library's
thread as the driver, and get each frame's buffer with
[](api:mln_acquired_frame_get_android_hardware_buffer). To resize the ring, use
[](api:mln_render_session_resize) instead of replacing it. Attach with three
buffers, and keep each frame acquired until the next one replaces it on screen.

## Draw each frame

Run the window's frame loop. Your renderer shows the frames instead of the
session.

When a frame renders, acquire it with [](api:mln_render_session_acquire_frame)
and get its texture for your backend. It takes the newest frame, and drops older
ones that you haven't acquired. The frame's slot is the index of its texture in
your ring.

When you're done with the frame, release it with
[](api:mln_acquired_frame_release), so the session can render into that texture
again. Pass [](api:MLN_GPU_SYNC_CPU_COMPLETE) if your reads have finished, or,
if they may still run on the GPU, a sync point of a kind that
[](api:mln_render_session_capabilities.consumer_sync_kinds) lists.

Keep at most one frame acquired, or the next frame waits for a free texture.
Release every acquired frame before you release the session.

<Snippet page="texture" region="acquire" />

## Resize the textures

The session renders at the size of your textures, so to resize, give it new
ones. First, release every acquired frame. Then create as many textures as
before at the new size, on the same device and in the same format, and set them
as the session's target. Once the replacement completes, destroy the old
textures.
