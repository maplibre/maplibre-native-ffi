A rendered feature query belongs to the render session and runs on the session's
owner thread, because it reads the frame that the renderer produced. The session
builds its renderer during the first `mln_render_session_render_update`, and a
query before that render update returns `MLN_STATUS_INVALID_STATE`.

A result describes the last frame that the session drew. Render again after a
camera move or a style change when the answer has to match the new state. A
query over an area whose tiles are still loading returns zero features, and the
same query returns features once those tiles arrive and render.

Screen coordinates are logical map pixels measured from the top-left of the
viewport, the same space that `mln_map_pixel_for_lat_lng` reports. A host that
tracks positions in physical device pixels divides them by the scale factor of
the render session.

The geometry states where to search. A point matches the exact position, and a
box matches a rectangle around it. A hit test uses a box with a few logical
pixels of tolerance around the position, because symbols and thin lines are
small targets. Box corners come in any order, and MapLibre clips the box to the
viewport.

On `MLN_STATUS_OK`, the query returns a result handle that the caller owns.
Destroy it with `mln_feature_query_result_destroy` once your host has copied
everything that it keeps.

<Code code={region(querySnippet, "query")} lang="c" title="query-rendered-features.c" />

`mln_feature_query_result_get` fills a `mln_queried_feature` whose `fields` mask
states which optional members the feature carries. Each member holds a view into
storage that the result owns. Copy every string, property value, and geometry
that your host keeps past the query, because those views stay valid only until
the result is destroyed.
