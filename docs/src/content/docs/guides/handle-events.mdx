Events are how MapLibre tells your host what happened: a style finished loading,
a frame is worth drawing, a download made progress, a resource failed. The
runtime copies each one into a queue, and your host reads that queue on the
runtime owner thread.

Draining is a loop rather than a single call. Poll until the queue reports that
nothing is left, because one pump can produce many events.

## Match an event to its source

One runtime serves every map created under it, and all of their events share one
queue. Check the source before anything else, or a second map's style load will

## Read a payload by its type

An event that carries structured data names the payload's type and length.
Check both before reading, because a runtime built from a newer header can carry
a longer payload than your host was compiled against, and a payload of the wrong
type is a different structure entirely.

## Events a host usually acts on

Draining is cheap, and most hosts ignore most of the queue. Four kinds are worth
handling early.

A style-loaded event means the style parsed and its sources exist, so this is
when a host adds its own sources and layers.

A render-update-available event means the map published something new to draw. A
render-frame-finished event carries a repaint flag, which asks for one more
frame so that camera animations and label placement can settle.

A loading-failed event carries the failure text in its message, and it is the
only report you get for a style or resource that never arrived.

Asynchronous failures generally arrive this way. A call that fails immediately
reports it through your binding's own error idiom, but a request that fails
later has nowhere else to go.

Destroying a map discards that map's queued events at once, so a host that
mirrors state from events reads what it needs while the map is live.
