MapLibre Native makes progress only while the host pumps the runtime. Call both
`mln_runtime_pump` and `mln_runtime_poll_event` from the runtime owner thread,
because either function returns `MLN_STATUS_WRONG_THREAD` from any other thread.
A pump call parks the owner thread when `timeout_ms` allows it, then drains the
owner-thread task queues, including the tasks that those tasks queue, and
services the runtime's own network and database work. Budget a pump as variable
work, because the drain runs to completion and one call can span a full style
parse.

Pumping advances the map, and a separate call draws a frame. The map publishes a
render update, and a later pump queues
`MLN_RUNTIME_EVENT_MAP_RENDER_UPDATE_AVAILABLE`. Calling
`mln_render_session_render_update` then draws that update on the render
session's owner thread. `MLN_RUNTIME_EVENT_MAP_RENDER_FRAME_FINISHED` carries
`needs_repaint`, and a true value means that the map needs one further frame for
camera animations and label placement to settle.

`timeout_ms` sets how long the call parks before it drains. Zero drains and
returns. A positive value parks for up to that many milliseconds. A negative
value parks until a wake arrives. Three things set the wake flag that releases a
parked call: the owner-thread run loop receiving work from any thread, the
runtime queueing an event, and `mln_wake_source_signal` from any thread. Pass a
positive bound so that a parked call returns even when no wake arrives, because
the runtime registers no timers of its own on that run loop. Call a parking pump
outside any lock that a signalling thread acquires.

## Pump on a thread of your own

When the runtime and the map live on a thread of their own, that thread parks
inside the pump, and the runtime's own work sets how often the loop runs. The
display thread attaches the render session and calls
`mln_render_session_render_update`. A pump call from the display thread returns
`MLN_STATUS_WRONG_THREAD`.

The two threads share three pieces of state: a flag that the pump thread sets
when a frame is due, a flag that the display thread sets to stop the loop, and a
wake source.

`mln_runtime_wake_source_acquire` returns `MLN_STATUS_WRONG_THREAD` from any
thread other than the runtime owner thread, so the pump thread acquires the
source before it starts the loop. A wake source holds its own reference to the
runtime's wake state, so the host destroys the two in either order. Call
