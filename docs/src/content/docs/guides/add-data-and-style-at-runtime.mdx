Anything a style document can express, you can also do at runtime. The API
deliberately speaks
[MapLibre Style Spec](https://maplibre.org/maplibre-style-spec/): sources and
layers go in as style-spec objects, property values and filters are style-spec
values including expressions. Nothing here re-invents a typed styling API, which
is why it stays in step with the spec across every layer type.

Wait for `MAP_STYLE_LOADED` before mutating. Additions target the style that is
loaded, and loading another one replaces them.

## Passing style-spec values

One thing differs from the web: values arrive as a **descriptor graph** rather
than a JSON string. A `mln_json_value` is a tagged union — string, number, bool,
array, object — that you build up in place, and the API copies it before
returning.

This is verbose in C by nature, and a single helper that converts your host
language's maps and lists into it pays for itself quickly. Number types are
meaningful: use the unsigned variant where the spec or an extension expects an
unsigned value.

## Sources

`add_style_source_json` takes any style-spec source object and is the general
path. Typed entry points exist where a source needs more than construction:

* **GeoJSON** — `add_geojson_source_url` or `add_geojson_source_data`, each with
  a matching `set_*` to swap in new data later. Note the add/set split: adding
  an ID that already exists is an error, not an update. Inline data comes in as
  geometry and feature descriptors rather than a JSON string.
* **Vector, raster, raster-DEM** — `add_*_source_url` for TileJSON or
  `add_*_source_tiles` for explicit tile URL templates, plus tile options: zoom
  range, attribution, scheme, bounds, tile size, and encoding.
* **Image** — `add_image_source_url` or `add_image_source_image`, with exactly
  four corner coordinates in top-left, top-right, bottom-right, bottom-left
  order.
* **Custom geometry** — `add_custom_geometry_source` registers `fetch_tile` and
  `cancel_tile` callbacks so you can generate tiles yourself.

<Aside type="caution">
  Custom geometry callbacks run on MapLibre's worker threads, not the map owner
  thread. Feeding tile data back in is a thread-affine map call, so queue it to
  the owner thread — calling it from the callback returns
  `MLN_STATUS_WRONG_THREAD` and the tile stays empty.
</Aside>

Removing a source fails while a layer still references it; remove the layers
first. `style_source_exists`, `get_style_source_type`, and
`list_style_source_ids` inspect what is loaded.

## Layers

`add_style_layer_json` takes any style-spec layer object containing at least
`id` and `type`, plus the ID to insert before — empty means "on top". Then
`move_style_layer` reorders and `remove_style_layer` deletes.

Three typed adders exist for layers that need more than a JSON object.
`add_hillshade_layer` and `add_color_relief_layer` check that their source is
actually raster-DEM. `add_location_indicator_layer` builds the user-location
puck, which is then driven per-frame by its own setters for location, bearing,
accuracy radius, and image name — the one place a per-frame typed setter beats
round-tripping JSON.

## Properties and filters

`set_layer_property` sets any paint or layout property by its style-spec name,
taking a style-spec value. Expressions are just arrays:
`["interpolate", ["linear"], ["zoom"], ...]`. `set_layer_filter` applies a
filter, and clearing it means passing an absent value. Getters return the
current value, or report absent for a property that was never set.

## Images

`set_style_image` registers a bitmap the style can reference from `icon-image`,
`fill-pattern`, and friends; calling it again with the same ID replaces the
image. Pixels are premultiplied RGBA8 with an explicit stride. Options carry
`pixel_ratio` — match it to the map's scale factor for crisp icons — and `sdf`
for signed-distance-field icons that `icon-color` can tint.

When a style references an image nobody supplied, the runtime emits
`MAP_STYLE_IMAGE_MISSING` with the ID. Handling that event by adding the image
is the intended flow; the repaint follows on its own.

## Light

`set_style_light_json` replaces the whole light object and
`set_style_light_property` sets one of `anchor`, `color`, `intensity`, or
`position`. Light steers fill-extrusion shading.
