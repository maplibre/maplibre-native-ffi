Anything a style document can express, you can also do at runtime. The API
speaks [MapLibre Style Spec](https://maplibre.org/maplibre-style-spec/):
sources and layers go in as style-spec objects, and property values and filters
are style-spec values, expressions included. That keeps the surface in step with
the spec across every layer type.

Wait for `MAP_STYLE_LOADED` before you mutate anything. Additions target the
loaded style, and loading another style replaces them.

## Passing style-spec values

Values arrive as a descriptor graph. A `mln_json_value` is a tagged union of
string, number, bool, array, and object that you build in place, and the API
copies it before returning.

C makes this verbose, so write one helper that converts your host language's
maps and lists into it. Number types carry meaning: use the unsigned variant
where the spec or an extension expects an unsigned value.

## Sources

`add_style_source_json` takes any style-spec source object. Typed entry points
cover the sources that need more than construction.

GeoJSON sources use `add_geojson_source_url` or `add_geojson_source_data`, each
with a matching `set_*` that swaps in new data later. Adding an ID that already
exists fails, so reach for the setter to replace data on a live source. Inline
data arrives as geometry and feature descriptors.

Both adders take `mln_geojson_source_options`, or null for the defaults. Those
options cover tiling zoom range, simplification tolerance, tile size and buffer,
clustering, and whether data updates apply synchronously, and they are fixed for
the life of the source, so the setters keep whatever the source was added with.

Set `synchronous_update` when a data swap needs to reach the next rendered
frame. MapLibre Native otherwise tiles updated data on a worker and shows it in
a later frame; the synchronous path runs that work inline on the thread driving
the update instead.

Vector, raster, and raster-DEM sources use `add_*_source_url` for TileJSON or
`add_*_source_tiles` for explicit tile URL templates, with tile options for zoom
range, attribution, scheme, bounds, tile size, and encoding.

Image sources use `add_image_source_url` or `add_image_source_image` and take
four corner coordinates in top-left, top-right, bottom-right, bottom-left order.

`add_custom_geometry_source` registers `fetch_tile` and `cancel_tile` callbacks,
which lets you generate tiles yourself.

<Aside type="caution">
  MapLibre runs custom geometry callbacks on its worker threads. Feeding tile
  data back is a thread-affine map call, so queue it to the map owner thread.
  Calling it from the callback thread returns `MLN_STATUS_WRONG_THREAD` and
  leaves the tile empty.
</Aside>

Removing a source fails while a layer still references it, so remove the layers
first. `style_source_exists`, `get_style_source_type`, and
`list_style_source_ids` report what is loaded.

## Layers

`add_style_layer_json` takes any style-spec layer object carrying at least `id`
and `type`, plus the ID to insert before. An empty before-ID puts the layer on
top. `move_style_layer` reorders and `remove_style_layer` deletes.

Three typed adders cover layers that need more than a JSON object.
`add_hillshade_layer` and `add_color_relief_layer` validate that their source is
raster-DEM. `add_location_indicator_layer` builds the user-location puck, driven
afterward by its own setters for location, bearing, accuracy radius, and image
name.

## Properties and filters

`set_layer_property` sets any paint or layout property by its style-spec name,
taking a style-spec value. Expressions are arrays, such as
`["interpolate", ["linear"], ["zoom"], ...]`. `set_layer_filter` applies a
filter, and passing an absent value clears it. Getters return the current value,
or report absent for a property nobody set.

The properties every layer shares get typed entry points instead:
`set_layer_source_layer`, `set_layer_source_id`, `set_layer_min_zoom`,
`set_layer_max_zoom`, and `set_layer_visibility`, each with a matching getter.
Prefer these over `set_layer_property` for those five. They read back, which
`get_layer_property` cannot do for them, and the two source setters reject a
layer type that takes no source rather than accepting the call and doing nothing.

An unset zoom bound reads back as an infinity, and the copy-out getters for
source-layer and source id answer a null buffer with zero capacity as a size
probe, so you can size a buffer before copying.

## Images

`set_style_image` registers a bitmap that the style can reference from
`icon-image` or `fill-pattern`. Calling it again with the same ID replaces the
image. Pixels are premultiplied RGBA8 with an explicit stride. Options carry
`pixel_ratio`, which you match to the map's scale factor for crisp icons, and
`sdf` for signed-distance-field icons that `icon-color` tints.

For a nine-patch sprite, set `stretch_x` and `stretch_y` to the intervals that
may scale, in image pixels. Pixels outside those intervals keep their size, so a
rounded button border stays crisp while its middle stretches. The intervals along
one axis run in increasing order without overlapping, and `set_style_image`
rejects any that break that shape. `content` sets the
box a symbol's label sits inside, and `text_fit_width` and `text_fit_height`
choose how the image resizes around that label for `icon-text-fit`.

Read those back with `get_style_image_info`, which reports the interval counts,
the content box, and the text fit, and with `copy_style_image_stretches` for the
intervals themselves. Passing null arrays with zero capacity probes the counts.

When a style references an image nobody supplied, the runtime emits
`MAP_STYLE_IMAGE_MISSING` with the ID. Handle that event by adding the image,
and the repaint follows.

## Light

`set_style_light_json` replaces the whole light object.
`set_style_light_property` sets one of `anchor`, `color`, `intensity`, or
`position`. Light steers fill-extrusion shading.

## Transitions

`set_style_transition_options` sets the style's global transition behavior:
`duration`, `delay`, and whether symbol placement changes cross-fade. These are
separate from camera animation options, which time camera moves. A paint
property's own style-spec transition, such as `fill-color-transition`, overrides
them for that property; they apply to every property that declares none.

Duration and delay are optional, and omitting one clears the style-wide
override. With no duration, paint property changes apply instantly, and
MapLibre Native's own 300 ms default governs the symbol placement cross-fade. A
continuous-mode map applies that same default to the pattern cross-fade across
integer zoom levels; a still-mode map fades those patterns instantly instead.
With no delay, transitions start immediately. A still-mode map ignores both
fields for paint property transitions, and renders each still image at a fixed
time point, so a property change reaches its final value in the next still image
whatever they hold.

Setting duration and delay replaces the whole configuration rather than merging
into what the style declared, so read the current options first when you mean to
change one field.

Loading a style replaces these options with the ones that style declares, so
apply an override after the style loads. What you read back afterwards depends
on the style: one with no `transition` member at all gets the parser's 300 ms
duration, while one carrying a `transition` object reports only the members that
object names. A style whose transition declares a delay alone therefore reports
no duration, so check whether a field is present rather than assuming a loaded
style sets it.

Placement transitions are always present and start enabled. Clearing them makes
symbol placement changes apply to the next rendered frame instead of fading in.
A host dragging a symbol-backed feature does that for the duration of the drag,
because the cross-fade otherwise leaves the rendered symbol trailing the pointer.
Restore it when the drag ends.
