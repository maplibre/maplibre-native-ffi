Camera state covers center, zoom, bearing, pitch, roll, field of view, padding,
and center altitude. It lives on the map, so you can move it before anything
draws. Transitions advance as you pump the runtime.

## Camera options

Camera options pair a field mask with values. MapLibre applies only the fields
you flag, so setting the zoom leaves the center where it was. Reading the camera
gives you a snapshot with the current values filled in.

Screen positions use logical pixels with the origin at top left, the same units
as the map's `width` and `height`.

`anchor` is input-only. It sets the screen point a camera command pivots around,
and snapshots leave it clear.

## Jump, ease, fly

Three commands apply camera options, and time separates them.

`jump_to` applies the camera immediately.

`ease_to` eases, and its duration defaults to zero. Without an explicit
`duration_ms` it behaves like a jump.

`fly_to` animates by default. Left alone it derives a duration from the flight
distance at 1.2 screenfuls per second.

Animation options also take a cubic easing curve, and `cancel_transitions()`
stops a transition in flight.

## Gestures

Pan, zoom, rotate, and pitch come in relative form, which wires straight to
input events. `move_by` pans in screen space, `scale_by` zooms by a factor
around an optional anchor, `rotate_by` rotates between two screen points, and
`pitch_by` takes a delta in degrees. Each has an animated variant with the same
zero-duration default as `ease_to`.

Absolute targets go through `jump_to`, `ease_to`, or `fly_to`.

`mln_map_set_gesture_in_progress()` tells the map that the commands you issue
belong to one live gesture. Set it when a pointer gesture starts and clear it
when the gesture ends, including when it is cancelled.
`mln_map_is_gesture_in_progress()` reads the flag back.

## Fit the camera to content

The `camera_for_*` family computes a camera that fits a bounding box, a
coordinate list, or a geometry into the current viewport, and returns it without
applying it. Pass the result to a transition to move there. Fit options add
padding, bearing, and pitch. Going the other way,
`lat_lng_bounds_for_camera()` reports the bounds a camera covers.

These answer against the current viewport, so the map's size decides the result.
Before you attach a render session, that size is the `width` and `height` you
created the map with.

## Constrain the camera

`mln_map_set_bounds()` limits where the camera may go through geographic bounds,
min and max zoom, and min and max pitch, using the same field-mask pattern.
Paired limits have to agree with each other. `mln_map_get_bounds()` reads back
the active constraints.

## Screen and world coordinates

`pixel_for_lat_lng` and `lat_lng_for_pixel` convert against the live map, with
batch variants for many points at once.

`mln_map_projection_create()` freezes the map's current transform into a
standalone projection object. That object answers the same conversions after the
camera moves on and after the map is gone, which is what overlay placement needs
between frames.

`projected_meters_for_lat_lng` and its inverse are stateless spherical Mercator
conversions that need no map. Metrics like meters-per-pixel are arithmetic on
top of those.

## Watch the camera move

Transitions emit `MAP_CAMERA_WILL_CHANGE`, `MAP_CAMERA_IS_CHANGING`, and
`MAP_CAMERA_DID_CHANGE`. Read `mln_map_get_camera()` during `IS_CHANGING` to
mirror an animating camera into your own UI.
