A vector source usually loads tiles from HTTP URL templates, as
[Add tile sources](/maplibre-native-ffi/guides/add-tile-sources/) describes. Use
a custom MVT vector source when the host already has those encoded tiles: a
bundled atlas, a database, or another process. The host answers each tile
request with protobuf bytes, or with an error.

A custom geometry source is the other host-callback source. It supplies GeoJSON
per tile rather than encoded vector tiles. Choose it when the host produces
GeoJSON features.

## Add the source and a layer

The source's fetch callback is required. Optional zoom bounds default to 0 and
18\. The source has no tile size, bounds, or attribution fields. Add it after a
style-loaded event, then add a layer that names the source and a `source-layer`
inside the tiles.

## Answer fetch on a worker, deliver on the owner thread

MapLibre calls fetch on a background worker. The callback must not call map
APIs. Copy the canonical tile ID, look the bytes up, and queue delivery onto the
map owner thread. Cancel is optional and best-effort; it can race with fetch.

On the owner thread, pass the copied bytes or a UTF-8 diagnostic. A zero-length
buffer is an empty tile. MapLibre copies accepted bytes before the call
returns. A delivery for a tile that is not awaiting a response is ignored and
still succeeds after validation.
