A source query reports the features that a source holds, including the features
that no layer draws. To find what a reader can see at a screen position instead,
use a rendered query, described in
[Query a Map](/maplibre-native-ffi/guides/query-a-map/).

The query belongs to the render session and runs on the
session's owner thread. The session builds its renderer during the first render update, and a query before that returns an invalid-state status.

## Run the query

A vector source needs source-layer IDs, because one vector tile holds several
layers and MapLibre reads the layers that you name. A vector query with
no source-layer ID returns zero features. A GeoJSON source holds a single layer
and ignores the field.

Name the source itself by its style source ID. That ID is the query's second
argument, and it differs from the source-layer IDs in the options.

<Code code={region(sourceFeatures, "query")} lang="c" title="query-source-features.c" />

Read the result count rather than the status when you expect features, because
an unknown source ID also produces an empty result with a success status.

<Code code={region(sourceFeatures, "read")} lang="c" title="query-source-features.c" />

The same query returns different features as the camera moves, because a query
covers the tiles that the source has loaded for the current camera. Tiles that
arrive later appear in the next query, and a source that no layer uses loads no
tiles at all.

## Expand a cluster

An extension query runs a named extension against one
feature of one source. The `supercluster` extension reads a GeoJSON source that
has clustering enabled, and its `leaves` field returns the features under one
cluster as a feature collection.

`supercluster` matches numbers by exact JSON type, so build the `limit` and
`offset` arguments as unsigned values.

<Code code={region(clusterLeaves, "arguments")} lang="c" title="cluster-leaves.c" />

The call names the source, the cluster feature, the extension, and the field
within that extension.

<Code code={region(clusterLeaves, "query")} lang="c" title="cluster-leaves.c" />

An extension can answer with a single value instead of a feature collection, so
the result states which of the two it holds. Check that before reading it.

<Code code={region(clusterLeaves, "leaves")} lang="c" title="cluster-leaves.c" />

Pass the cluster feature to the extension query exactly as a source query
returned it. `supercluster` reads the `cluster_id` property by the same rule, so
a double or a signed integer counts as absent. A feature descriptor copied out
of a query result keeps the JSON type of every property. A host that rebuilds
the feature through a JSON layer that stores every number as a double receives a
successful query with an empty result.
