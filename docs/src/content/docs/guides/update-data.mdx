A GeoJSON source accepts new inline data or a new URL. Both commands replace the
whole dataset in runtime submission order. A host that tracks individual
features keeps its own collection and publishes the collection after each
change.

Initialize the source with an empty feature collection. Every later update uses
the same source ID, preserving the layers that draw it.

<Code code={region(liveUpdates, "add")} lang="c" title="geojson-live-updates.c" />

For each change, the host serializes its collection as one UTF-8 GeoJSON
FeatureCollection. The snippet writes each position as a point feature into a
caller-provided buffer.

<Code code={region(liveUpdates, "features")} lang="c" title="geojson-live-updates.c" />

One call publishes the complete buffer view to the source. MapLibre parses or
copies the bytes before returning, so the host can reuse the buffer afterward.

<Code code={region(liveUpdates, "publish")} lang="c" title="geojson-live-updates.c" />

Every update re-tiles the whole dataset. When a feed delivers faster than the
display refreshes, collect the messages that arrive between frames and publish
once per frame.

## Synchronous updates

MapLibre tiles updated data on a worker thread. New features appear in a later
frame, and the update call does not extend the current frame. Use this default
for most feeds.

Set the synchronous-update option when the next frame must include the update.
Examples include a simulation that advances with rendering and a still image
captured immediately after an update. Tiling then runs on native worker threads.
A large dataset can delay the render update that publishes the new tiles.

<Code code={region(liveUpdates, "options")} lang="c" title="geojson-live-updates.c" />

Choose the synchronous-update option when adding the source. Changing it later
requires removing every layer that draws the source and then replacing the
source.
