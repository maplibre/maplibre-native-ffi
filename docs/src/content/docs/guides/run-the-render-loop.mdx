The host decides when to request frames. A core-worker session runs its graphics
work on a native thread. A caller-driver session also needs service on the
host's graphics thread.

## Request frames

Each frame demand carries a host token that its result returns. To render on
demand, keep one render-if-needed demand armed with the wait-for-update flag,
and re-arm it as each result arrives. During animations, pace demands to the
display. Set the present flag for a target that shows frames in a window or
view.

## Service a caller driver

When the driver-work wake fires, schedule service on the graphics thread, and
return from the wake without waiting. Keep servicing while presentation is
paused, because attachment, queries, readback, resize, and detach also need
driver work.

If the graphics thread can no longer run,
[abandon the target](/maplibre-native-ffi/guides/attach-a-render-target/#resize-and-release).

## Drain results

When the frame wake fires, schedule a drain on the host loop. Drain until the
queue is empty, read each batch, and release it.

Each result's outcome tells the host when to demand again, as the
[session reference](/maplibre-native-ffi/reference/c/render__session_8h.html)
describes. To read a texture target, acquire its frame and follow the
synchronization that the
[texture reference](/maplibre-native-ffi/reference/c/texture_8h.html) states.
[Render a static image](/maplibre-native-ffi/guides/render-a-static-image/)
shows CPU readback.
