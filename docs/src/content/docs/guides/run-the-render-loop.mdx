MapLibre Native advances runtime and map work on the runtime's core-owned
scheduler thread. The host does not pump that scheduler. The host render loop
drains notifications, observes render-update events, and draws through a render
session on the graphics thread.

## Schedule notification drains

Create one notification source for the host receiver that handles the runtime.
Pass it to runtime creation, then either install a callback or integrate the
binding's equivalent suspension primitive.

The callback may run on any native thread. It carries no event data and must not
call the C API. Schedule a later ready-batch drain on the receiver's execution
context instead.

A notification is level-triggered. Drain the source's owned ready batch, inspect
each endpoint by its reported stride, and release the batch. When it contains the
runtime-events endpoint, drain runtime events until the typed drain reports an
empty queue. An operation endpoint means that operation reached a terminal
disposition and can be inspected. Coalesced callbacks lose no readiness.

## Request frames from runtime events

Select render-update-available and render-frame-finished before loading the map's
style. When the runtime-events endpoint becomes ready, drain the event queue and
match each map event to the map that the render session displays.

A render-update-available event means the map published new render state. Set the
host's render request. A render-frame-finished event carries a repaint flag; set
another request when that flag is true so camera animations and label placement
continue.

Map and camera commands run on the scheduler thread after their input is copied.
Any host thread may submit them. A command returns an ID; its command-finished
event reports committed, superseded, failed, or cancelled. Use a runtime barrier
when later host work must wait for every preceding submission to become
terminal.

## Draw on the graphics thread

The thread that attaches a render session owns that session for its lifetime.
Keep render-session calls on that graphics thread even though runtime, map, and
projection handles are callable from any thread.

Draw when the host render request is set. Only a rendered result clears the
request. A no-update result and a pending-size result mean that the map has not
published render state for the session's current extent. A target-not-ready
result means that the target had no frame to draw into, so retain the request
for another turn.

Resize the target's platform allocation and submit the map resize command before
the next draw. The resize command is the sole authority for the map's logical
width, height, and scale factor.

## Close the loop

Stop host frame callbacks, then close the render session on its graphics thread.
Start and await map close after the session is gone. Start and await runtime
close after every map and pending child creation is gone. Close the notification
source last. A failed close preflight leaves the parent handle open so the host
can close the remaining child and retry.
