MapLibre Native advances runtime and map work on its native scheduler. A render
session advances through either a native graphics worker or a narrow service
call on the host graphics thread. Neither contract requires a host runtime pump.

## Submit frame demand

Submit a nonblocking frame demand from any thread. It carries a host token,
presentation time, optional deadline, flags, and a coalescing boundary. Matching
demands may coalesce before work starts, but every accepted demand produces one
terminal result record. Presentation time selects render state. A positive
deadline uses the host's monotonic clock; when it expires before work begins,
the demand terminates as deadline missed. Neither timestamp supplies cadence.

A core-worker session wakes its serial graphics worker. A caller-driver session
makes its driver-work notification endpoint ready. Map updates use the same
paths, so progress does not depend on runtime-event drains or display callbacks.

The host may submit demand from a display source, after an earlier result, or
from another scheduler. A demand captures the current extent generation. Its
result identifies the token and the map-update, extent, and frame generations
that the driver used.

## Service a caller driver

When the driver-work endpoint is ready, schedule the driver-service call on the
thread or realm where the target's graphics context is usable. The first
successful call fixes that graphics-thread identity. Service work in serialized
calls until the endpoint drains. Continue service while presentation callbacks
are paused, because attach, resize, queries, readback, barriers, and detach also
use the mailbox.

A core-worker session rejects the service call because its native worker already
owns execution. WGL, EGL, existing WebGL contexts, and browser WebGPU use caller
drivers. Transferable Metal, Vulkan, and `OffscreenCanvas` WebGL targets can use
core workers.

If the graphics owner cannot run again, abandon the target. Leaving ready work
unserviced can leave operations pending indefinitely.

## Drain results and present

Frame readiness is level-triggered. Drain an owned frame-result batch from any
thread when its endpoint is ready. Only one batch may remain live per session;
release it before another drain. Keep draining until the queue is empty.

A rendered result means that a frame was presented or became available for
acquisition. No update and size pending wait for a newer map update. Target not
ready waits for host target readiness or paced retry. Superseded means that a
newer demand replaced this demand within the same coalescing boundary. Deadline
missed means that work did not begin before the positive deadline. These
outcomes have different retry conditions, so preserve them in host pacing.

Owned texture acquisition is nonblocking and leases the oldest completed slot
that is not already acquired. Wait for or submit work after its producer sync.
Release the acquired handle with consumer-completion sync when host GPU work
reads the texture. CPU-complete sync is valid only when that work completed
before release. The release operation completes when the slot is reusable.

Use a session barrier when later work must wait for every preceding render item
to become terminal and for the driver to observe a minimum map-update
generation. A barrier orders work; it does not request a frame.
