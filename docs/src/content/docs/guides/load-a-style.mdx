A style decides everything the map draws: which tiles it fetches, which layers
it paints, and in what order. A map with no style renders nothing, so loading
one is the first thing to do with a new map.

## Choose where the style comes from

Set a style URL when a server publishes it, which is the usual case for a hosted
base map. MapLibre fetches it through the same resource system that loads tiles,
so a URL also reaches any cache, offline region, or request transform that the
runtime has.

<Code code={region(loadStyle, "url")} lang="c" title="load-style.c" />

Set the style text instead when your host already holds it: a base style shipped
inside the application, or one composed at runtime. MapLibre parses and copies
it before the call returns.

<Code code={region(loadStyle, "json")} lang="c" title="load-style.c" />

Either call returns as soon as the map accepts the request. The style, its
sources, its glyphs, and its first tiles arrive across the pumps that follow,
and the map reports a style-loaded event once the style has parsed and its
sources exist. A loading-failed event reports the other outcome and carries the
failure text.
[Handle Events](/maplibre-native-ffi/guides/handle-events/) covers reading both.

## Everything you add belongs to one loaded style

Sources, layers, images, and layer properties that your host adds belong to the
style that was loaded when they were added. Loading another style discards all
of them.

A host that adds its own data therefore adds it after the style-loaded event,
and does the same again after every later style load. A host that switches base
maps at runtime keeps whatever it needs to replay, and replays it each time.

The camera is the exception, and it survives a style load unchanged.
