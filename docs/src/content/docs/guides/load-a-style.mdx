A style defines the tiles, layers, and drawing order of a map. Load one before
rendering a new map.

## Choose where the style comes from

Set a style URL for a hosted base map. Like a tile request, it uses the
runtime's cache, offline regions, and resource transform.

<Code code={region(loadStyle, "url")} lang="c" title="load-style.c" />

Set style text when the host already has the document, such as a bundled base
style or one composed at runtime.

<Code code={region(loadStyle, "json")} lang="c" title="load-style.c" />

Wait for the style-loaded event before adding host sources and layers. Observe
the command completion for failures and the event stream for later resource
errors. [Handle events](/maplibre-native-ffi/guides/handle-events/) covers
reading the event stream.

## Load a local style

Use a `file://` URL for an explicit file path. Use `asset://style.json` to load
`style.json` from the runtime's asset path, which you can set to any directory.

On Android, the asset path defaults to `/android_asset`. After
[platform initialization](/maplibre-native-ffi/install/#android), both
`asset://style.json` and `file:///android_asset/style.json` read APK
`assets/style.json`.

For APK-bundled PMTiles sources, use `pmtiles://asset://map.pmtiles`. Add
`pmtiles` to the app's `androidResources.noCompress` list for byte-range reads.

## Replay additions after a style load

Sources, layers, images, and layer properties that your host adds belong to the
style that was loaded when they were added. Loading another style discards all
of them.

A host adds its own data after the style-loaded event and repeats those changes
after every later style load. A host that switches base maps keeps the changes
that it needs to replay.

The [style reference](/maplibre-native-ffi/reference/c/style_8h.html) defines
style commands and their completion outcomes.
