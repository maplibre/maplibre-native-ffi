This guide walks through the lifecycle every integration shares: create a
runtime, create a map, load a style, pump work, and tear everything down in
order. It renders nothing yet — rendering attaches on top of this skeleton in
[Render to a Surface](/maplibre-native-ffi/guides/render-to-a-surface/) or
[Render to a Texture](/maplibre-native-ffi/guides/render-to-a-texture/).

## Create the runtime

The runtime owns scheduler state and event storage for one **owner thread**.
Create it on the thread that will pump it; every later runtime, map, and render
session call must run on that same thread, and the API reports
`MLN_STATUS_WRONG_THREAD` (or the binding equivalent) otherwise. Each thread
may own one live runtime.

Runtime options select where the runtime reads and writes files:

* `cache_path` — the ambient cache database. Tiles, glyphs, and sprites persist
  here between runs. The special value `":memory:"` keeps the cache in memory.
* `asset_path` — the filesystem root that `asset://` URLs resolve against.
* `maximum_cache_size` — the ambient cache size cap in bytes, when set.

Options are copied at creation; later resource-loading configuration is covered
in [Configure Resource Loading](/maplibre-native-ffi/guides/configure-resource-loading/).

## Create the map

A map belongs to a runtime. Map options set the initial viewport and behavior:

* `width` / `height` — the initial logical viewport in UI pixels. Attaching a
  render session replaces these with the render target extent.
* `scale_factor` — the UI-to-device pixel scale. It is fixed for the map's
  lifetime and selects sprite, glyph, and raster density.
* `map_mode` — `CONTINUOUS` for a live updating map, `STATIC` for a one-off
  still of an arbitrary viewport, or `TILE` for a one-off still of a single
  tile.

The map is independent of any render target: you can load styles, move the
camera, mutate sources and layers, and observe events without ever attaching
one.

## Load a style

`set_style_url` fetches a style document (and everything it references)
asynchronously; `set_style_json` parses an inline style document. Both are
"map commands": a success status means the request was accepted, not that the
style loaded. Watch the runtime events for the outcome:

* `MLN_RUNTIME_EVENT_MAP_STYLE_LOADED` — the style parsed and its sources are
  ready for runtime additions.
* `MLN_RUNTIME_EVENT_MAP_LOADING_FAILED` — loading failed; the event carries an
  error message.

Inline JSON with a syntax error may also fail the `set_style_json` call itself,
so check both the return status and the events.

## Pump the runtime

MapLibre Native makes progress only when the host pumps the runtime. The loop
has two halves, always on the owner thread:

1. `mln_runtime_run_once()` drains the owner-thread run loop: every queued task
   plus the tasks those tasks enqueue, expired timers, and ready network and
   database work. The promise is drain, not slice — one call can span a full
   style parse, and an idle runtime returns promptly.
2. `mln_runtime_poll_event()` pops queued events, one per call, until it
   reports none. Event payloads and message strings are borrowed; copy anything
   you keep.

How often you pump is a host decision: GUI examples pump once per frame,
headless tools pump in a loop with a short sleep. The events worth knowing on
day one:

| Event                                     | Meaning                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------- |
| `MAP_STYLE_LOADED` / `MAP_LOADING_FAILED` | Style outcome (above)                                                           |
| `MAP_RENDER_UPDATE_AVAILABLE`             | The map has new content to render; drive your frame loop from this              |
| `MAP_CAMERA_WILL/IS/DID_CHANGE`           | Camera transition progress                                                      |
| `MAP_STILL_IMAGE_FINISHED` / `FAILED`     | A requested still image completed (static/tile modes)                           |
| `MAP_STYLE_IMAGE_MISSING`                 | The style referenced an image ID nobody provided; add it with `set_style_image` |

## A complete minimal lifecycle

This example creates a runtime and map, loads a style, pumps until the style
loads (or fails), and tears down. It needs network access for the style URL.

```c
#include <maplibre_native_c.h>
#include <stdio.h>
#include <string.h>
#include <time.h>

int main(void) {
  mln_runtime_options options = mln_runtime_options_default();
  options.cache_path = ":memory:";

  mln_runtime* runtime = NULL;
  if (mln_runtime_create(&options, &runtime) != MLN_STATUS_OK) return 1;

  mln_map_options map_options = mln_map_options_default();
  map_options.width = 512;
  map_options.height = 512;
  map_options.scale_factor = 1.0;

  mln_map* map = NULL;
  if (mln_map_create(runtime, &map_options, &map) != MLN_STATUS_OK) {
    mln_runtime_destroy(runtime);
    return 1;
  }

  bool loaded = false;
  if (mln_map_set_style_url(
          map, "https://tiles.openfreemap.org/styles/bright") != MLN_STATUS_OK)
    goto done;

  // A pump count is not elapsed time: on a slow network this can spin
  // through every iteration before the response lands. Bound the wait on
  // the clock and yield between pumps instead.
  const time_t deadline = time(NULL) + 30;
  while (!loaded && time(NULL) < deadline) {
    mln_runtime_run_once(runtime);
    mln_runtime_event event = {.size = sizeof(event)};
    bool has_event = false;
    while (mln_runtime_poll_event(runtime, &event, &has_event) == MLN_STATUS_OK &&
           has_event) {
      if (event.type == MLN_RUNTIME_EVENT_MAP_STYLE_LOADED) loaded = true;
      if (event.type == MLN_RUNTIME_EVENT_MAP_LOADING_FAILED) {
        fprintf(stderr, "style failed: %.*s\n", (int)event.message_size,
                event.message);
        goto done;
      }
    }
    // A real host sleeps briefly here, or drives this from its event loop,
    // rather than spinning.
  }

done:
  mln_map_destroy(map);
  mln_runtime_destroy(runtime);
  return loaded ? 0 : 1;
}
```

## Tear down in order

Handles form a parent-child chain — runtime → map → render session — and a
parent refuses to close while children are live (`MLN_STATUS_INVALID_STATE`).
Close in reverse order of creation:

1. Detach and destroy any render session.
2. Destroy the map.
3. Destroy the runtime.

Two teardown behaviors catch new integrators:

* **Closing a map discards its queued events.** There is no flush and no
  terminal event, so snapshot any state you mirror from events before closing
  the map that produced them.
* **Non-deterministic cleanup does not save you.** Finalizers, GC, and `Drop`
  report leaks but do not destroy thread-affine handles on the bindings' behalf
  in the general case; explicit close on the owner thread is the contract.

<Aside>
  Language-specific owner-thread helpers: Go callers must `runtime.LockOSThread()`
  before creating a runtime and keep its lifecycle on the locked goroutine. .NET
  ships an `OwnerThread` helper that runs closures on a dedicated owner thread.
  Zig bindings take an explicit allocator and report native diagnostics through a
  `DiagnosticStore` you pass at runtime creation. Kotlin/JVM needs
  `--enable-native-access=ALL-UNNAMED`.
</Aside>
