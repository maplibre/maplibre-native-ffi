You assemble three things: a runtime, a map, and a render session. You call the
function that lets MapLibre do work, and you decide when frames happen. No map
view drives a loop for you.

## Everything happens on one thread

The runtime, its maps, and their render sessions are owner-thread affine.
Whichever thread creates the runtime owns all of it, and the API rejects calls
from any other thread with `MLN_STATUS_WRONG_THREAD`. One thread owns one
runtime, so choose that thread before you write anything else.

Resource transforms and providers are the exception. MapLibre invokes those on
its own network and worker threads, and the
[C API reference](/maplibre-native-ffi/reference/c/) says so on each one.

## Create a runtime

The runtime owns the scheduler and the event queue. Its options decide where
bytes live.

`cache_path` sets the ambient cache database, where tiles, glyphs, and sprites
persist between runs. `":memory:"` keeps that database in memory.
[Offline regions](/maplibre-native-ffi/guides/download-offline-regions/) share
it, so pass a filesystem path if you want them.

`asset_path` sets the filesystem root that `asset://` URLs resolve against.

`maximum_cache_size` caps the ambient cache in bytes. Runtime creation reads
that field only when `flags` includes
`MLN_RUNTIME_OPTION_MAXIMUM_CACHE_SIZE`.

## Create a map

A map belongs to a runtime, and one runtime can own several.

`width` and `height` set the logical viewport in UI pixels, the same units the
camera and hit-testing use. Attaching a render session overwrites both with the
session's extent, so they matter until you attach one.

`scale_factor` sets the UI-to-device pixel ratio. It is fixed for the life of
the map and picks which sprite, glyph, and raster densities MapLibre requests
for every frame, so set it to the density you intend to render at.

`map_mode` selects `CONTINUOUS` for a live map, `STATIC` for one-off stills of
an arbitrary viewport, or `TILE` for one-off stills of a single tile.

A map works without a render target. You can load a style, move the camera,
add sources, and read events on one that has yet to draw a frame.

## Load a style

`mln_map_set_style_url()` fetches a style document and everything it references.
`mln_map_set_style_json()` takes one inline. Both are commands: an OK status
means MapLibre accepted the request. The style resolves later, and the outcome
arrives as `MAP_STYLE_LOADED` or `MAP_LOADING_FAILED`, which carries a message.
A URL that 404s returns OK and then fails through the event stream, so report
style errors from there.

## Let MapLibre do work

MapLibre makes progress while you pump the runtime, in two calls.

`mln_runtime_run_once()` drains the owner thread's work: queued tasks, the tasks
those tasks queue, expired timers, and ready network and database work. It
returns promptly on an idle runtime. One call runs until that work finishes and
can span an entire style parse, so budget for it as work, not as a fixed
per-frame slice.

`mln_runtime_poll_event()` pops one queued event per call until it reports none
left. Every map under the runtime shares this queue, so compare `event.source`
against the map you care about. Payload and message pointers stay valid only
until the next poll. Copy what you keep.

| Event                                     | Meaning                                                    |
| ----------------------------------------- | ---------------------------------------------------------- |
| `MAP_STYLE_LOADED` / `MAP_LOADING_FAILED` | How the style request resolved                             |
| `MAP_RENDER_UPDATE_AVAILABLE`             | The map has new content to draw, and drives a frame loop   |
| `MAP_RENDER_FRAME_FINISHED`               | A frame completed, and reports whether another is needed   |
| `MAP_CAMERA_WILL` / `IS` / `DID_CHANGE`   | Camera transition progress                                 |
| `MAP_STILL_IMAGE_FINISHED` / `FAILED`     | A requested still image resolved, in static and tile modes |
| `MAP_STYLE_IMAGE_MISSING`                 | The style wants an image ID nobody supplied                |

How often you pump is your call: once per frame, or in a loop until the event
you want arrives.

## Tear down in order

A runtime owns maps and a map owns its render session. A parent refuses to close
while a child is live, returning `MLN_STATUS_INVALID_STATE`, so close in the
reverse of the order you created: session, map, runtime.

Destroying a map discards that map's queued events. MapLibre gives you no flush
and no final event, so read the state you mirror from events while the map is
still live.

Finalizers, `Drop`, and `using` blocks in the bindings report leaks. They do not
close a thread-affine handle on its owner thread for you. Close it yourself.
