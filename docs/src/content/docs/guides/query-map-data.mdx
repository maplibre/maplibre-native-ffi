Queries read map data back out: what is drawn at a point on screen, and what a
source holds.

They hang off the render session, because they read what the renderer produced.
A session has to be attached and has to have rendered once before a query
returns anything.

## Query rendered features

`query_rendered_features` takes a screen geometry in logical pixels, either a
point, a box, or a line string, and returns the features drawn under it. Options
narrow the query to a list of layer IDs and can apply a
[style-spec filter](https://maplibre.org/maplibre-style-spec/expressions/)
expression as JSON.

Pass layer IDs. Without them the query matches everything rendered at that spot,
background fills included.

Each result carries the feature, its source ID, its source layer where known,
and its feature state where set. You own the results. The pointers inside them
belong to the result handle, so copy anything that has to outlive it, then
destroy the handle.

## Query source features

`query_source_features` reads a loaded source, skipping layer visibility,
styling, and the viewport. Vector sources need their source layer IDs in the
options, and GeoJSON sources ignore them.

It reads the source data the renderer currently holds, which in practice means
the tiles loaded for the current camera. Features in tiles that have not loaded
are absent, and results change as the camera moves. Query the underlying dataset
when you need coverage of the whole source.

## Expanding clusters

`query_feature_extensions` hands a feature you previously queried back to a
source's extension. The built-in one is `supercluster`: give it a cluster
feature from a clustered GeoJSON source and ask for its `"leaves"`,
`"children"`, or `"expansion-zoom"`.

<Aside type="caution" title="Unsigned numbers, specifically">
  Supercluster reads `cluster_id` from the feature's properties, and the `limit`
  and `offset` arguments, strictly as unsigned JSON values. A JSON layer that
  turns every number into a double produces an empty result and a success
  status, with no error to chase. Feed the queried feature back unmodified,
  since it preserves its property types, and build `limit` and `offset` as
  unsigned.
</Aside>

## Feature state

Feature state attaches per-feature key-value data, such as `"hover": true`, that
style expressions read through `feature-state`. Per-feature appearance can then
change while the style stays put.

State lives on the session's renderer, which has two consequences. The renderer
has to exist first, so render once after the style loads before you set state.
State also does not survive a resize or a reattach, so reapply it after either.
Setting or removing state requests a repaint.

The selector picks the target. `source_id` is required, `source_layer_id`
disambiguates vector sources, `feature_id` picks the feature, and `state_key`
removes a single entry.
