Queries answer questions about what the map is showing: what the user tapped,
what a source holds, what a cluster expands to.

They hang off the **render session**, not the map — because they read what was
actually rendered. That means a session must be attached and must have rendered
at least once before a query returns anything.

## What did the user tap?

`query_rendered_features` takes a screen geometry — a point, a box, or a line
string, in logical pixels — and returns the features drawn under it. Options
narrow it to a list of layer IDs and can apply a
[style-spec filter](https://maplibre.org/maplibre-style-spec/expressions/)
expression as JSON.

For a tap handler, pass the layer IDs you care about. Without them the query
matches everything rendered there, background fills included.

Each result carries the feature, its source ID, its source layer where known,
and its feature state where set. The results are copies you own; the pointers
inside them belong to the result handle, so copy anything that has to outlive
it, then destroy the handle.

## What is in this source?

`query_source_features` reads out of a loaded source, skipping layer visibility,
styling, and the viewport. Vector sources need their source layer IDs in the
options; GeoJSON sources ignore them.

The important limit: it reads only the source data the renderer currently
holds — in practice, the tiles loaded for the current camera. Features in tiles
that have not loaded are simply absent, and results change as the camera moves.
It is not a search over your whole dataset. If you need that, query the dataset
itself.

## Expanding clusters

`query_feature_extensions` hands a feature you previously queried back to a
source's extension. The built-in one is `supercluster`: give it a cluster
feature from a clustered GeoJSON source and ask for its `"leaves"`,
`"children"`, or `"expansion-zoom"`.

<Aside type="caution" title="Unsigned numbers, specifically">
  Supercluster reads `cluster_id` from the feature's properties, and the `limit`
  and `offset` arguments, strictly as **unsigned** JSON values. A JSON layer that
  turns every number into a double produces an empty result and a success
  status — no error to chase. Feed the queried feature back unmodified (its
  property types are preserved), and build `limit` and `offset` as unsigned.
</Aside>

## Feature state

Feature state attaches per-feature key-value data — `"hover": true` and friends
— that style expressions read through `feature-state`. It is how you highlight
what the user is pointing at without touching the style.

State lives on the session's renderer, which has two consequences worth
planning around: the renderer has to exist first, so render once after the style
loads before setting state; and state does not survive a resize or a reattach,
so reapply it when either happens. Setting or removing state requests a repaint
on its own.

The selector picks the target: source ID (always), source layer ID (to
disambiguate vector sources), feature ID, and a state key when removing a single
entry.
