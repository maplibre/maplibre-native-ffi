A static map renders one image per request rather than redrawing as data and
camera state change. A tile service, a thumbnail job, or an export asks for an
image, waits for it, and reads the pixels into host memory.

Static mode is fixed when the map is created, so a host that produces images
creates a map for that, as
[Create a Map](/maplibre-native-ffi/guides/create-a-map/) describes. Reading
pixels back also requires a session-owned texture, because that is the one
target kind the map allocates and can copy out of.

## Request one image

Create the map at the size that the render target uses. A session attached at a
different size sets the map size on the map's owner thread, and the map keeps
its previous size until the next pump, so a request made before the new size
reaches the map produces an update that renders nothing.

Render on every turn of the loop, because a static map advances its loading
through the render calls themselves. The runtime reports a still-image-finished
event from the map's run loop, and that event can arrive before or after the
render call that produced the pixels. The image is ready once the event has
arrived and a render call has reported a frame, which is why the loop waits for
both.
