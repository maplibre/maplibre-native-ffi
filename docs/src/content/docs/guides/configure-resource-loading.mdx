By default the map fetches what its style names over the network and caches the
results. You can rewrite those URLs, answer the requests yourself, or move the
cache.

## Cache and asset paths

Runtime options set these at creation, covered in
[Create and Run a Map](/maplibre-native-ffi/guides/create-and-run-a-map/).
`cache_path` points at the ambient cache database and `asset_path` at the root
that `asset://` URLs resolve against. To cap the ambient cache in bytes, call
`set_maximum_ambient_cache_size_start`, covered in
[Download offline regions](/maplibre-native-ffi/guides/download-offline-regions/).

## Rewriting URLs

A resource transform rewrites the URL of every network request the runtime
makes, which is how you attach an API key, swap a host, or route through a
proxy. Register it at any point, including with maps already running.

MapLibre invokes the callback on a worker or network thread, so keep it
thread-safe and quick, and call no other C API function from inside it beyond
`mln_resource_transform_response_set_url()`. The callback changes the URL and
nothing else, leaving headers, bodies, and cache policy alone. Returning a
non-OK status leaves the URL unchanged, and the request still proceeds.

A style names sprites, glyphs, and tiles on origins you do not control, and your
transform runs for those requests too. Match the host you own before you attach
a credential to it.

Transforms apply to MapLibre's online file source, including nested PMTiles
range requests. They skip `file`, `asset`, and `mbtiles` URLs, along with
requests a provider already intercepted.

## Serving requests yourself

A resource provider intercepts network requests and answers them from your code,
which covers custom URL schemes, app storage, and your own HTTP stack. Register
it before you create any map from the runtime.

The callback runs synchronously on a network thread and returns one of two
decisions. Pass-through leaves the request to MapLibre, and you touch the handle
no further. Handle gives you the request: complete it with a response, inline or
later from any thread, then release it once. Completion is one-shot, the C API
copies response bytes before returning, and a long fetch should check whether
MapLibre cancelled the request before finishing the work.

MapLibre resolves the built-in schemes `file`, `asset`, `mbtiles`, and `pmtiles`
before your provider sees them. Every other scheme reaches the provider,
including invented ones like `custom://style.json`, which become failed HTTP
requests if you pass them through. Serving those is what the provider is for.

<Aside>
  The runtime stores the provider callback and its `user_data` by reference and
  can invoke them until the runtime is destroyed. Keep both alive that long.
</Aside>

## Process-global switches

Two settings apply per process.

`mln_network_status_set()` toggles whether the online file source starts
requests. Going offline halts new network work until reachability returns. Drive
it from your platform's connectivity monitor.

`mln_log_set_callback()` installs the process-global log sink. MapLibre can
invoke it on logging or worker threads while holding internal locks, so keep it
thread-safe, fast, and free of calls back into the API. Return "consumed" to
suppress the platform logger. The callback and its state must stay valid until
`mln_log_clear_callback()` replaces or clears it.

On Android, call `mln_android_init` once at startup, or HTTPS requests cannot
validate TLS against the platform trust store.
