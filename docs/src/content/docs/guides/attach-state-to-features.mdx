Feature state is data that your host attaches to one feature at runtime and that
style expressions read while the map draws. You write the styling rule once and
each feature supplies its own input to it, so one style covers selection, hover,
a live value, or a computed status.

Feature state belongs to the [render session](/maplibre-native-ffi/concepts/),
because the session's renderer owns the tiles that the state applies to. That
renderer exists after the first `mln_render_session_render_update` that follows
a style load. Render once before you set state; a call made earlier returns
`MLN_STATUS_INVALID_STATE`. Every feature-state call runs on the session's owner
thread.

A selector names what the state belongs to: the source ID, the source layer ID
for a vector source, the feature ID, and, for removal, one state key. Feature
IDs match as text, so a feature whose GeoJSON `id` is the number 7 is selected
by `"7"`. Setting state writes the keys of the object that you pass, leaves the
feature's other keys at their current values, and requests a repaint. Removal
depends on how much of the selector you supply: a state key removes one entry, a
feature ID alone removes that feature's whole state, and a selector with neither
one removes the state of every feature in the source layer.

An expression reads one key with `feature-state`, and its fallback value applies
to every feature that has no value for that key. A circle layer that enlarges
the selected feature reads
`["case", ["boolean", ["feature-state", "selected"], false], 10, 5]` for
`circle-radius`.

`mln_render_session_get_feature_state` copies the state that the session holds
into a snapshot handle that you own. The snapshot holds an empty object when the
source or the feature has no state.

The state lives as long as the session's renderer. A resize and a render target
replacement through `mln_<backend>_surface_set_target` or
`mln_<backend>_borrowed_texture_set_target` keep that renderer, and the feature
state with it. A renderer compiles its shaders for a fixed pixel ratio, so any
of those calls that changes the scale factor builds a new renderer, as does
destroying a session and attaching another. Feature state starts empty on a new
renderer. A host that needs the state to survive a display change keeps its own
copy and sets it again after the next render update.
