One database holds everything that a runtime caches, and `cache_path` in the
runtime options sets that database's path. The field defaults to `:memory:`, so
pass a writable filesystem path to keep the cached resources across runs of the
host.

Two kinds of storage share the database. The ambient cache holds the resources
that the map already fetched, and MapLibre evicts from it to stay under a byte
budget. Offline regions are the storage that a host requests: MapLibre downloads
every resource that a defined area needs, and keeps those resources outside the
ambient budget. Download a region when the application must draw a known area
without a network.

Database calls are asynchronous, and they share one shape. A `_start` function
validates its arguments, returns an operation ID, and queues the work. The
runtime later queues one `MLN_RUNTIME_EVENT_OFFLINE_OPERATION_COMPLETED` event
that carries the ID and the operation's own result status. That result status is
separate from the status that the `_start` call returned. An operation that
produces a value holds that value until the matching `_take_result` call
consumes it, and every operation holds runtime state until a take or
`mln_runtime_offline_operation_discard` releases it.

## Download a region

A region definition names a style and an area. MapLibre resolves the definition
into every tile, glyph, and sprite that the style needs across the zoom range,
and stores them under one region ID.

<Code code={region(offlineRegion, "define")} lang="c" title="offline-region.c" />

The create call takes a tagged definition. A tile pyramid covers a bounding box,
and a geometry region covers a GeoJSON shape.

<Code code={region(offlineRegion, "tag")} lang="c" title="offline-region.c" />

Creation also takes opaque metadata bytes, and the database stores them with the
region. A host records what the region holds there, such as a name or a version.
MapLibre copies the definition, the style URL, and the metadata bytes before the
call returns.

<Code code={region(offlineRegion, "create")} lang="c" title="offline-region.c" />

Taking the result produces a snapshot handle that carries the region record. A
failed take leaves the operation live, so discard the operation when the host
stops retrying.

<Code code={region(offlineRegion, "result")} lang="c" title="offline-region.c" />

The region ID is the part of the record that the remaining calls need.

<Code code={region(offlineRegion, "region-id")} lang="c" title="offline-region.c" />

The runtime queues progress and error events for observed regions only, so call
`mln_runtime_offline_region_set_observed_start` for the new region ID first.
Setting the download state to active then starts the download, and MapLibre
fetches the region's resources while the host pumps the runtime.

<Code code={region(offlineRegion, "download")} lang="c" title="offline-region.c" />

`MLN_RUNTIME_EVENT_OFFLINE_REGION_STATUS_CHANGED` carries resource counts, tile
counts, and stored bytes for every change.
`MLN_RUNTIME_EVENT_OFFLINE_REGION_RESPONSE_ERROR` reports one resource that
failed while the rest of the download continues. Drain both from the runtime
that owns the region, as described in
[Concepts](/maplibre-native-ffi/concepts/).

<Code code={region(offlineRegion, "progress")} lang="c" title="offline-region.c" />

Setting the download state to `MLN_OFFLINE_REGION_DOWNLOAD_INACTIVE` pauses a
download, and setting it active again resumes from the resources that MapLibre
already stored.

## Read what the database holds

stored, because region records outlive the runtime that wrote them. One list
operation covers the whole database.

<Code code={region(offlineStorage, "list")} lang="c" title="offline-storage.c" />

Taking the result produces a list handle that the host owns. Destroy that handle
after reading the entries.

<Code code={region(offlineStorage, "result")} lang="c" title="offline-storage.c" />
