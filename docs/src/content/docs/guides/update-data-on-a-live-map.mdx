A GeoJSON source that is already on the style accepts new data through one of
two calls. `mln_map_set_geojson_source_data` takes geometry and feature
descriptors inline. `mln_map_set_geojson_source_url` names a new URL that
MapLibre fetches through its resource system. Both calls run on the map's owner
thread, and both replace the whole dataset. A host that tracks individual
features therefore keeps its own collection and publishes that collection on
every change.

By default MapLibre tiles updated data on a worker thread, and the new features
appear in one of the frames that follow the update. Set `synchronous_update` on
the source options when an update has to reach the very next frame. A simulation
step that advances in lockstep with rendering is one such case, and a still
image captured immediately after an update is another. Tiling then runs inline
during the update pass inside `mln_render_session_render_update`, on the render
session's owner thread, so a large dataset extends that frame.

each item in its own collection. A point geometry carries a single coordinate.

Updating the source keeps its ID, so every layer that draws it keeps drawing,
and the source keeps the options that it was added with. Removing the source and
adding a replacement requires removing each layer that uses it first, because
`mln_map_remove_style_source` returns `MLN_STATUS_INVALID_STATE` while a layer
uses the source. A change to the options themselves, clustering in particular,
is the one case that needs a fresh source, and
[Show a GeoJSON Dataset](/maplibre-native-ffi/guides/show-a-geojson-dataset/)
covers adding one.

Every update re-tiles the whole dataset. When a feed delivers faster than the
display refreshes, collect the messages that arrive between frames and publish
once per frame.
