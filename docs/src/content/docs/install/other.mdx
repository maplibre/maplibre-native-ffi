## C library

Each [release](https://github.com/maplibre/maplibre-native-ffi/releases/latest)
publishes the C library for every preset. The
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
rebuilds the same assets from `main` under a fixed tag. To build the library
yourself, see the
[development overview](/maplibre-native-ffi/development/overview/).

A preset name has the form `<platform>-<arch>-<backend>`, as in
`macos-arm64-metal` or `linux-gnu-x64-vulkan`. OpenGL presets name their context
provider in place of the backend: `egl`, `wgl`, or `webgl`.

### Build against a prefix

Download `maplibre-native-c-<preset>.tar.gz` and unpack it. The directory it
holds, `maplibre-native-c-<preset>`, is the install prefix. The prefix's
`share/maplibre-native-c/artifact.json` records the release `version` and the
`commit` it was built from, which matches a snapshot archive to its source after
the snapshot moves on.

With CMake, set `maplibre-native-c_DIR` to the prefix's package config directory
and link the imported target. This also works with cross-compilation toolchains
that restrict package searches to a sysroot:

```cmake title="CMakeLists.txt"
find_package(maplibre-native-c CONFIG REQUIRED)
target_link_libraries(app PRIVATE maplibre-native-c::maplibre-native-c)
```

```bash frame="terminal"
cmake -S . -B build -Dmaplibre-native-c_DIR=<prefix>/lib/cmake/maplibre-native-c
cmake --build build
```

To link the complete static archive, use
`maplibre-native-c::maplibre-native-c-static`. The target supplies its system
dependencies and defines `MLN_STATIC`. On platforms that ship only a static
library, the primary target also links the complete archive.

For other build systems, use pkg-config:

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
cc -std=c23 main.c $(pkg-config --cflags --libs maplibre-native-c) -o main
```

On Windows, add `<prefix>/bin` to `PATH` or copy `maplibre-native-c.dll` beside
the executable. Linux, FreeBSD, and macOS executables find the library through
the rpath that pkg-config adds.

A static musl executable can link the complete archive for the non-rendering
APIs, but rendering loads EGL or Vulkan drivers at run time and needs a dynamic
loader.

### xmake

With xmake 3.1.2 or later, select a release by its distribution repository tag:

```lua title="xmake.lua"
add_repositories("maplibre https://github.com/maplibre/maplibre-native-ffi-distribution.git v{{version}}")
add_requires("maplibre-native-c {{version}}", {configs = {backend = "vulkan"}})

target("app")
    set_kind("binary")
    add_files("main.c")
    add_packages("maplibre-native-c")
```

Omit `backend` to take the platform's default. On Linux, set `libc = "musl"` in
`configs` when building for musl.

### vcpkg

Register the distribution repository as a Git registry. Its baseline is the
commit that the release's tag names:

```bash frame="terminal"
git ls-remote https://github.com/maplibre/maplibre-native-ffi-distribution 'refs/tags/v{{version}}^{}'
```

```json title="vcpkg-configuration.json"
{
  "registries": [
    {
      "kind": "git",
      "repository": "https://github.com/maplibre/maplibre-native-ffi-distribution",
      "baseline": "<commit>",
      "packages": ["maplibre-native-c"]
    }
  ]
}
```

vcpkg also needs a baseline for its default registry. Keep the manifest's
`builtin-baseline`, or set `"default-registry": null` when the project takes no
other vcpkg packages.

Select exactly one backend feature: `opengl`, `metal`, or `vulkan`. The port
supplies Release binaries to both Debug and Release builds. Link the CMake
target as for [a prefix](#build-against-a-prefix).

```json title="vcpkg.json"
{
  "dependencies": [{ "name": "maplibre-native-c", "features": ["vulkan"] }]
}
```

### Conan

With Conan 2, clone the distribution repository and add it as a local recipe
index. Pull the clone to see later releases.

```bash frame="terminal"
git clone https://github.com/maplibre/maplibre-native-ffi-distribution.git
conan remote add maplibre-native-ffi ./maplibre-native-ffi-distribution --type=local-recipes-index
conan install --requires="maplibre-native-c/{{version}}" --build=missing \
  -o "maplibre-native-c/*:backend=vulkan" -g CMakeDeps -g CMakeToolchain
```

The recipe links the complete static library through the
`maplibre-native-c::maplibre-native-c` target. `backend` takes `metal`,
`opengl`, `vulkan`, `webgpu`, or `default`, the platform's default. On Linux,
add `-o "maplibre-native-c/*:libc=musl"` for musl. On Windows, pass
`-s compiler.runtime=static`.

### Link from Android native code

An Android app's native code can link the C library from a Kotlin runtime AAR
through [Prefab](https://developer.android.com/build/native-dependencies), with
CMake or ndk-build:

```kotlin title="build.gradle.kts"
android {
  buildFeatures {
    prefab = true
  }
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-opengl-android:{{version}}")
}
```

```cmake title="CMakeLists.txt"
find_package(maplibre-native-c REQUIRED CONFIG)
target_link_libraries(app PRIVATE maplibre-native-c::maplibre-native-c)
```

### Add the XCFramework to an Apple app

`MaplibreNativeC.xcframework.zip` holds the framework `MaplibreNativeC` for
every Apple Metal preset. Add it to a Swift package as a binary target, with the
zip's checksum from `SHA256SUMS`.

```swift title="Package.swift"
.binaryTarget(
  name: "MaplibreNativeC",
  url: "https://github.com/maplibre/maplibre-native-ffi/releases/download/<tag>/MaplibreNativeC.xcframework.zip",
  checksum: "<checksum>"
)
```

Swift imports the module `MaplibreNativeC`, and C includes
`<MaplibreNativeC/maplibre_native_c.h>`. The plugin header is the submodule
`MaplibreNativeC.Plugin`.

## Bindings

Each binding wraps the C library in one language. Most carry or download the C
library, and the sections that need an installed prefix say so.

### .NET

Add the binding and the runtime for your backend from
[NuGet](https://www.nuget.org/packages/Maplibre.NativeFfi). The runtime carries
the native library.

```bash frame="terminal"
dotnet add package Maplibre.NativeFfi
dotnet add package Maplibre.NativeFfi.Runtime.Vulkan
```

Take one runtime package:

- `Maplibre.NativeFfi.Runtime.OpenGL`
- `Maplibre.NativeFfi.Runtime.Metal`
- `Maplibre.NativeFfi.Runtime.Vulkan`

For Windows with MinGW, take `Maplibre.NativeFfi.Runtime.OpenGL.MinGW` or
`Maplibre.NativeFfi.Runtime.Vulkan.MinGW` instead. These alternatives carry
Windows assets only; the packages above use MSVC on Windows.

For the snapshot channel, download the packages from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
into a directory, and add that directory as a package source.

```bash frame="terminal"
gh release download unstable-native-snapshot --repo maplibre/maplibre-native-ffi --pattern '*.nupkg' --dir packages
```

```xml title="nuget.config"
<configuration>
  <packageSources>
    <add key="maplibre-snapshot" value="packages" />
  </packageSources>
</configuration>
```

A snapshot's version is the next release's version with a `-dev` suffix, so take
the newest prerelease of both packages.

```bash frame="terminal"
dotnet add package Maplibre.NativeFfi --prerelease
dotnet add package Maplibre.NativeFfi.Runtime.Vulkan --prerelease
```

### Dart

Add the package from [pub.dev](https://pub.dev/packages/maplibre_native_ffi).

```bash
dart pub add maplibre_native_ffi
```

The package downloads the C library for the target when it builds.

To build against your own copy of the [C library](#build-against-a-prefix), name
it in your application's pubspec. Name an install prefix, or a directory holding
installs one level down, such as a CMake build root. A relative path resolves
against the pubspec. A Git dependency on the package needs a local build.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      local_build: ../maplibre-native-ffi/build
```

For the snapshot channel, depend on the package from Git at `main`. Download
`maplibre-native-c-<preset>.tar.gz` for your target from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot),
unpack it beside the pubspec, and name the unpacked prefix in `local_build`.

```bash frame="terminal"
curl -L https://github.com/maplibre/maplibre-native-ffi/releases/download/unstable-native-snapshot/maplibre-native-c-macos-arm64-metal.tar.gz | tar -xz
```

```yaml title="pubspec.yaml"
dependencies:
  maplibre_native_ffi:
    git:
      url: https://github.com/maplibre/maplibre-native-ffi
      path: bindings/dart
      ref: main

hooks:
  user_defines:
    maplibre_native_ffi:
      local_build: maplibre-native-c-macos-arm64-metal
```

The snapshot rebuilds `main` once a day. If `main` has moved past it, set `ref`
to the commit that the release names.

To override the default backend, map an OS to a backend in `backend`.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      backend:
        android: vulkan
```

The backends are `opengl`, `metal`, and `vulkan`. The keys are `android`, `ios`,
`linux`, `macos`, and `windows`.

To download through a mirror, name its base URL in `release_url`. The mirror
serves each release tag as a directory that holds that release's archives.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      release_url: https://mirror.internal/maplibre-native-ffi
```

### Go

Add the package at the release's version.

```bash frame="terminal"
go get github.com/maplibre/maplibre-native-ffi/bindings/go/maplibre@v{{version}}
```

cgo finds the C library through pkg-config. Unpack the release's
[C library](#build-against-a-prefix) for your preset, then export
`PKG_CONFIG_PATH` before you build.

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
```

On Windows, cgo uses MSYS2's Clang to link either the MSVC or MinGW C DLL. Use
MINGW64 on x64 or CLANGARM64 on ARM64. Set `CC` to that environment's
`bin/clang.exe` and `PKG_CONFIG` to its `bin/pkgconf.exe`, and put the C
library's `bin` directory and the MSYS2 environment's `bin` directory on `PATH`.

For the snapshot channel, take the module from `main` and the C library from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot).

```bash frame="terminal"
go get github.com/maplibre/maplibre-native-ffi/bindings/go/maplibre@main
```

### Python

Install the binding and the runtime for your backend from
[PyPI](https://pypi.org/project/maplibre-native-ffi/). The runtime holds the
binding's native extension, with the C library linked in.

```bash frame="terminal"
pip install maplibre-native-ffi maplibre-native-ffi-runtime-vulkan
```

Take one runtime distribution. Importing `maplibre_native_ffi` raises
`ImportError` unless exactly one is installed.

- `maplibre-native-ffi-runtime-opengl`
- `maplibre-native-ffi-runtime-metal`
- `maplibre-native-ffi-runtime-vulkan`

Windows also offers `maplibre-native-ffi-runtime-opengl-mingw` and
`maplibre-native-ffi-runtime-vulkan-mingw`, built with MinGW and bundled with
its runtime DLLs. Choose one instead of the corresponding MSVC runtime.

Use Python 3.12 or later. To choose the runtime by platform, add an environment
marker to each:

```toml title="pyproject.toml"
[project]
dependencies = [
  "maplibre-native-ffi",
  "maplibre-native-ffi-runtime-metal; sys_platform == 'darwin'",
  "maplibre-native-ffi-runtime-opengl; sys_platform != 'darwin'",
]
```

For the snapshot channel, install both distributions from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot).
A snapshot's version is a development release of the next release, so pip takes
it only with `--pre`.

```bash frame="terminal"
pip install --pre maplibre-native-ffi maplibre-native-ffi-runtime-vulkan --find-links https://github.com/maplibre/maplibre-native-ffi/releases/expanded_assets/unstable-native-snapshot
```

With uv, name the snapshot release as a flat index for both distributions:

```toml title="pyproject.toml"
[project]
dependencies = ["maplibre-native-ffi", "maplibre-native-ffi-runtime-vulkan"]

[[tool.uv.index]]
name = "maplibre-snapshots"
url = "https://github.com/maplibre/maplibre-native-ffi/releases/expanded_assets/unstable-native-snapshot"
format = "flat"
explicit = true

[tool.uv.sources]
maplibre-native-ffi = { index = "maplibre-snapshots" }
maplibre-native-ffi-runtime-vulkan = { index = "maplibre-snapshots" }
```

The snapshot release holds only the latest wheels, so a lockfile that names an
older snapshot fails to install once the snapshot moves on.

### Swift

Add the package from its
[distribution repository](https://github.com/maplibre/maplibre-native-ffi-distribution),
which each release tags with its version, and depend on the `MaplibreNativeFFI`
product.

```swift title="Package.swift"
.package(
  url: "https://github.com/maplibre/maplibre-native-ffi-distribution",
  exact: "{{version}}"
)
```

```swift title="Package.swift"
.product(name: "MaplibreNativeFFI", package: "maplibre-native-ffi-distribution")
```

On Apple platforms, the package takes the C library from the release's
[XCFramework](#add-the-xcframework-to-an-apple-app). Its `MaplibreNativeC`
product is that library, for a native target that calls the C API itself.

On Linux, install the [C library](#build-against-a-prefix), then export
`PKG_CONFIG_PATH` before you build. SwiftPM drops the rpath that pkg-config
names, so pass the prefix's `lib` directory to the linker, or put it on the
loader's search path when you run.

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
swift build -Xlinker -rpath -Xlinker <prefix>/lib
```

For the snapshot channel, depend on this repository at `main`, whose package
always builds against an installed C library. SwiftPM takes the package identity
from the repository name, so name it as `maplibre-native-ffi`. Install the
[C library](#build-against-a-prefix) from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
and export `PKG_CONFIG_PATH` as for Linux.

```swift title="Package.swift"
.package(url: "https://github.com/maplibre/maplibre-native-ffi", branch: "main")
```

```swift title="Package.swift"
.product(name: "MaplibreNativeFFI", package: "maplibre-native-ffi")
```

### TypeScript

Add the package from [npm](https://www.npmjs.com/package/@maplibre/native-ffi)
with exactly one backend package: `@maplibre/native-ffi-opengl`,
`@maplibre/native-ffi-metal`, `@maplibre/native-ffi-vulkan`, or
`@maplibre/native-ffi-webgpu`.

```bash frame="terminal"
npm install @maplibre/native-ffi @maplibre/native-ffi-vulkan
```

The backend package installs the C library for the host. Use Node.js 24.11, Bun
1.4.3, Deno 2.9.7, or later. Deno imports the package as
`npm:@maplibre/native-ffi` and needs `--allow-ffi --allow-read --allow-env`.

On Windows, the default backend packages use MSVC. For a MinGW host on x64,
install `@maplibre/native-ffi-opengl-mingw` or
`@maplibre/native-ffi-vulkan-mingw` instead.

In a browser, `@maplibre/native-ffi-opengl` renders with WebGL 2 and
`@maplibre/native-ffi-webgpu` with WebGPU. Serve `maplibre_native_ffi.mjs` and
`maplibre_native_ffi.wasm` from the backend's `-wasm32` package as static files,
such as from Vite's `public` directory, and load them before any other call:

```ts
import { loadModule, RuntimeHandle } from "@maplibre/native-ffi";

await loadModule(new URL("/maplibre_native_ffi.mjs", location.href));
const runtime = await RuntimeHandle.create();
```

For an embedded Hermes runtime, install the facade and import its Hermes entry:

```ts
import { RuntimeHandle } from "@maplibre/native-ffi/hermes";
```

The native host links the C library and the package's `native/hermes` CMake
target against the matching Hermes JSI library. It installs
`mln::hermes::Module` before loading JavaScript and supplies a scheduler for the
runtime thread. See the entry's package documentation and `module.h` for the
host's threading and lifetime requirements. On Android, initialize the C API's
platform services with the application context. The host supplies graphics
objects and the surface for presentation.

npm has no snapshot channel. To try `main`, pack the packages for your preset in
a checkout of this repository, then install the tarballs:

```bash frame="terminal"
mise run //bindings/typescript:pack linux-gnu-x64-vulkan
npm install path/to/maplibre-native-ffi/bindings/typescript/build/npm/*.tgz
```

On OpenHarmony, add `@maplibre/native-ffi-opengl` or
`@maplibre/native-ffi-vulkan` from
[OHPM](https://ohpm.openharmony.cn/#/en/detail/@maplibre%2Fnative-ffi-opengl),
and import the binding from that package.

```bash frame="terminal"
ohpm install @maplibre/native-ffi-opengl
```

To try `main`, pack the package for your preset, then install the HAR:

```bash frame="terminal"
mise -E ohos run //bindings/typescript:pack-ohpm ohos-arm64-egl
ohpm install path/to/maplibre-native-ffi/bindings/typescript/build/ohpm/native-ffi-opengl-0.0.0.har
```

### Zig

Add the package from a release.

```bash frame="terminal"
zig fetch --save https://github.com/maplibre/maplibre-native-ffi/releases/download/v{{version}}/maplibre-native-ffi-zig.tar.gz
```

```zig title="build.zig"
const maplibre = b.dependency("maplibre_native_ffi", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("maplibre_native_ffi", maplibre.module("maplibre_native_ffi"));
```

The build downloads the C library for the target. To override the default
backend, pass `.backend` as `.opengl`, `.metal`, or `.vulkan`. Mac Catalyst
builds target `aarch64-maccatalyst`. Windows needs the `msvc` ABI, which Zig
doesn't choose by default, so build with `-Dtarget=x86_64-windows-msvc` or
`-Dtarget=aarch64-windows-msvc`.

An installed executable finds the library beside itself on Windows and in
`../lib` elsewhere, so install it from the package's `prefix`. On Windows, run
the installed executable; elsewhere, `zig build run` also finds the library in
Zig's package directory:

```zig title="build.zig"
const library = switch (target.result.os.tag) {
    .windows => "bin/maplibre-native-c.dll",
    .macos, .maccatalyst => "lib/libmaplibre-native-c.dylib",
    else => "lib/libmaplibre-native-c.so",
};
const prefix = maplibre.namedLazyPath("prefix");
b.getInstallStep().dependOn(&b.addInstallFile(prefix.path(b, library), library).step);
```

Zig has no libc for Android, so a build for it uses the NDK's. Pass the
dependency `.@"system-root"` as the NDK's `sysroot` directory, and
`.@"target-libc"` as a libc file in the format that `zig libc` prints. The file
names `usr/include` and its target subdirectory as the include directories, and
the target's CRT directory, `usr/lib/<target>/<API level>`, as both `crt_dir`
and `cc_dir`. Call `setLibCFile` with the same file on each artifact that
imports the module. An app ships `libmaplibre-native-c.so` in its `lib/<abi>`
directory.

The
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
publishes the same package from `main`. Run the same `zig fetch --save` again to
move to the latest snapshot.

```bash frame="terminal"
zig fetch --save https://github.com/maplibre/maplibre-native-ffi/releases/download/unstable-native-snapshot/maplibre-native-ffi-zig.tar.gz
```

To build against your own copy of the [C library](#build-against-a-prefix), pass
the dependency its install prefix as `local-build`, which serves the one target
it was built for. A path from the command line must be absolute. A Git
dependency on the repository needs a local build.

```zig title="build.zig"
const maplibre = b.dependency("maplibre_native_ffi", .{
    .target = target,
    .optimize = optimize,
    .@"local-build" = b.option(std.Build.LazyPath, "local-build", "MapLibre Native C library build"),
});
```
