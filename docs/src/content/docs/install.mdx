Choose a render backend first. Prefer Metal for Apple platforms, OpenGL for
emulators and virtual machines, and Vulkan for other platforms. Then install the
C library, a binding for your language, or both. Each section covers its tagged
releases, where they exist, and its snapshot channel.

## C library

Each [release](https://github.com/maplibre/maplibre-native-ffi/releases/latest)
publishes the C library for every preset. The
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
rebuilds the same assets from `main` under a fixed tag. To build the library
yourself, see the
[development overview](/maplibre-native-ffi/development/overview/).

A preset name has the form `<platform>-<arch>-<backend>`, as in
`macos-arm64-metal` or `linux-gnu-x64-vulkan`. OpenGL presets name their
context provider in place of the backend: `egl`, `wgl`, or `webgl`.
[Platforms](#platforms) lists the backends and providers for each platform.

### Build against a prefix

Download `maplibre-native-c-<preset>.tar.gz` and unpack it. The archive root is
the install prefix.

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
cc -std=c23 main.c $(pkg-config --cflags --libs maplibre-native-c) -o main
```

On Windows, add `<prefix>/bin` to `PATH` or copy `maplibre-native-c.dll` beside
the executable. Linux and macOS executables find the library through the rpath
that pkg-config adds.

Linux prefixes also carry a complete static archive. A static musl executable
can link it for the non-rendering APIs, but rendering loads EGL or Vulkan
drivers at run time and needs a dynamic loader.

### Add the XCFramework to an Apple app

`MaplibreNativeC.xcframework.zip` holds the framework `MaplibreNativeC` for
every Apple Metal preset. Add it to a Swift package as a binary target, with the
zip's checksum from `SHA256SUMS`.

```swift title="Package.swift"
.binaryTarget(
  name: "MaplibreNativeC",
  url: "https://github.com/maplibre/maplibre-native-ffi/releases/download/<tag>/MaplibreNativeC.xcframework.zip",
  checksum: "<checksum>"
)
```

Swift imports the module `MaplibreNativeC`, and C includes
`<MaplibreNativeC/maplibre_native_c.h>`. The plugin header is the submodule
`MaplibreNativeC.Plugin`.

## Bindings

Each binding wraps the C library in one language. Most carry or download the C
library, and the sections that need an installed prefix say so.

### Kotlin

Add Maven Central, the binding, and the runtime for your backend. The runtime
carries the native library for every ABI.

```kotlin title="build.gradle.kts"
repositories {
  mavenCentral()
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi:{{version}}")
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:{{version}}")
}
```

Take one runtime module:

- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-opengl`
- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-metal`
- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan`

On Android, initialize platform services before you create a runtime, as
[Android](#android) describes.

For the snapshot channel, add the Maven snapshot repository and take the
snapshot version of both modules. The runtime modules and Android
initialization match the release.

```kotlin title="build.gradle.kts"
repositories {
  maven("https://central.sonatype.com/repository/maven-snapshots/") {
    content { includeGroup("org.maplibre.nativeffi") }
  }
  mavenCentral()
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi:0.1.0-SNAPSHOT")
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:0.1.0-SNAPSHOT")
}
```

#### Kotlin/Wasm in the browser

<Aside type="caution" title="Repository only">
  The `wasmJs` target publishes no library and no browser module yet, so only
  Gradle builds inside this repository, such as its test suite, can use it.
</Aside>

Build the browser module for your backend's preset, then serve
`maplibre-native-kotlin.mjs` and `maplibre-native-kotlin.wasm` from
`bindings/kotlin/wasm/build/<preset>/install` side by side, from a cross-origin
isolated page as [Web](#web) describes.

```bash frame="terminal"
mise -E emscripten run //bindings/kotlin:wasm-module emscripten-wasm32-webgl
```

Load the module by its URL before any other call:

```kotlin title="Main.kt"
import org.maplibre.nativeffi.Maplibre

suspend fun main() {
  Maplibre.loadModule("/maplibre-native-kotlin.mjs")
}
```

`BrowserGraphics` imports the page's `GPUDevice`, canvas context, or
`WebGL2RenderingContext` as the handles that render target descriptors take.

- `Maplibre.NativeFfi.Runtime.Vulkan`

### Dart

Add the package from [pub.dev](https://pub.dev/packages/maplibre_native_ffi).

```bash
dart pub add maplibre_native_ffi
```

The package downloads the C library for each target when it builds. Releases
include macOS for arm64 alone.

To build against your own copy of the [C library](#build-against-a-prefix),
name it in your application's pubspec. Name an install prefix, or a build
directory that holds `<preset>/install` for each target. A relative path
resolves against the pubspec. A Git dependency on the package needs a local
build.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      local_build: ../maplibre-native-ffi/build
```

Each target uses Metal on Apple platforms, OpenGL on Android, and Vulkan
elsewhere. Map an OS to a different backend in `backend`.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      backend:
        android: vulkan
```

The backends are `opengl`, `metal`, and `vulkan`. The keys are `android`,
`ios`, `linux`, `macos`, and `windows`.

To download through a mirror, name its base URL in `release_url`. The mirror
serves each release tag as a directory that holds that release's archives.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      release_url: https://mirror.internal/maplibre-native-ffi
```

### Python

<SnapshotOnly />

Depend on the distribution for your backend and resolve it from the snapshot
index. The wheels contain the native library.

```toml title="pyproject.toml"
[project]
dependencies = ["maplibre-native-ffi-vulkan"]

[[tool.uv.index]]
name = "maplibre-snapshots"
url = "https://maplibre.github.io/maplibre-native-ffi/simple/"
explicit = true

[tool.uv.sources]
maplibre-native-ffi-vulkan = { index = "maplibre-snapshots" }
```

This configuration uses uv, and resolves only this package from the snapshot
index.

Take one distribution:

- `maplibre-native-ffi-opengl`
- `maplibre-native-ffi-metal`
- `maplibre-native-ffi-vulkan`

### Rust

Add the crate from [crates.io](https://crates.io/crates/maplibre-native-ffi).

```bash frame="terminal"
cargo add maplibre-native-ffi
```

The build script downloads the C library for the target. Releases include macOS
for arm64 alone, and the published crates do not support Emscripten.

Each target uses Metal on Apple platforms, OpenGL on Android and OpenHarmony,
and Vulkan elsewhere. Enable one backend feature, `opengl`, `metal`, or
`vulkan`, to choose another. A feature on a target-specific dependency applies
to that target alone.

```toml title="Cargo.toml"
[dependencies]
maplibre-native-ffi = "{{version}}"

[target.'cfg(target_os = "android")'.dependencies]
maplibre-native-ffi = { version = "{{version}}", features = ["vulkan"] }
```

To build against your own copy of the [C library](#build-against-a-prefix), set
`MAPLIBRE_NATIVE_FFI_LOCAL_BUILD` to an absolute path. Name an install prefix,
or a build directory that holds `<preset>/install` for each target. A Git or
path dependency on the crate needs a local build.

```toml title=".cargo/config.toml"
[env]
MAPLIBRE_NATIVE_FFI_LOCAL_BUILD = { value = "../maplibre-native-ffi/build", relative = true }
```

To download through a mirror, set `MAPLIBRE_NATIVE_FFI_RELEASE_URL` to its base
URL. The mirror serves each release tag as a directory that holds that
release's archives.

### Swift

<SnapshotOnly />

The package manifest at the repository root defines the Swift package.

```swift title="Package.swift"
.package(url: "https://github.com/maplibre/maplibre-native-ffi", branch: "main")
```

Depend on the `MaplibreNativeFFI` product. SwiftPM takes the package identity
from the repository name rather than from the manifest, so name it as
`maplibre-native-ffi`.

```swift title="Package.swift"
.product(name: "MaplibreNativeFFI", package: "maplibre-native-ffi")
```

Install the [C library](#build-against-a-prefix), then export `PKG_CONFIG_PATH`
before you build.

### TypeScript

<Aside type="caution" title="Build from source">
  The TypeScript binding publishes no packages yet. Build it from a checkout of
  this repository.
</Aside>

The binding runs on Node.js 24.11, Bun 1.4.3, Deno 2.9.7, and later, on Linux
with glibc and on macOS. Pack it for your preset in the checkout, then install
the tarballs, which contain the native library:

```bash frame="terminal"
mise run //bindings/typescript:pack linux-gnu-x64-vulkan
npm install path/to/maplibre-native-ffi/bindings/typescript/build/npm/*.tgz
```

When several backend packages are installed, set `MAPLIBRE_NATIVE_FFI_BACKEND`
to `opengl`, `metal`, or `vulkan`. Deno imports the package as
`npm:@maplibre/native-ffi` and needs `--allow-ffi --allow-read --allow-env`.

On OpenHarmony, build the library with
`mise -E ohos run //bindings/typescript:build <preset>`, ship it with the SDK's
`libc++_shared.so` in the application's `libs/<abi>` directory, and bundle
`bindings/typescript/src/arkts.ts`.

### Zig

## Platforms

### Linux

Linux runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

### macOS

macOS runs the Metal, Vulkan, and OpenGL backends, with EGL as the OpenGL
context provider. Apple provides neither Vulkan
nor EGL, so a host that chooses one of those backends loads
[MoltenVK](https://github.com/KhronosGroup/MoltenVK) or
[ANGLE](https://chromium.googlesource.com/angle/angle) itself.

### Windows

Windows runs the Vulkan and OpenGL backends, with WGL as the OpenGL context
provider.

### Android

Android runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

An Android app using Kotlin/JVM depends on a Kotlin runtime AAR, which carries
the native library for every ABI.

```kotlin title="build.gradle.kts"
implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:{{version}}")
```

A Kotlin/Native target gets the native library from its runtime KLIB, and the
app packages nothing else for it.

An app's native code, built with CMake or ndk-build, links the runtime AAR's
library through [Prefab](https://developer.android.com/build/native-dependencies).
The app can use any `ANDROID_STL`.

```kotlin title="build.gradle.kts"
android {
  buildFeatures {
    prefab = true
  }
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-opengl-android:{{version}}")
}
```

```cmake title="CMakeLists.txt"
find_package(maplibre-native-c REQUIRED CONFIG)
target_link_libraries(app PRIVATE maplibre-native-c::maplibre-native-c)
```

Android platform initialization is required once per process, before creating
a runtime. Pass an `android.content.Context`; every binding exposes this call
under its own name.

### iOS

iOS runs the Metal backend, on the device, in the simulator, and under Mac
Catalyst. A Mac Catalyst app links the Mac Catalyst library in place of the
macOS library.

### OpenHarmony

OpenHarmony runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

### Web

Emscripten runs the WebGPU and OpenGL backends, with WebGL as the OpenGL context
provider.

A page that loads a browser module must be cross-origin isolated: serve it with
the `Cross-Origin-Opener-Policy: same-origin` and
`Cross-Origin-Embedder-Policy: require-corp` headers. The module reserves a
fixed 512 MB heap.
