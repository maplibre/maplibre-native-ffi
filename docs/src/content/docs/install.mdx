Choose a render backend first. Prefer Metal for Apple platforms, OpenGL for
emulators and virtual machines, and Vulkan for other platforms. Then install the
C library, a binding for your language, or both. Each section covers its tagged
releases, where they exist, and its snapshot channel.

## C library

Each [release](https://github.com/maplibre/maplibre-native-ffi/releases/latest)
publishes the C library for every preset. The
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
rebuilds the same assets from `main` under a fixed tag. To build the library
yourself, see the
[development overview](/maplibre-native-ffi/development/overview/).

A preset name has the form `<platform>-<arch>-<backend>`, as in
`macos-arm64-metal` or `linux-gnu-x64-vulkan`. OpenGL presets name their
context provider in place of the backend: `egl`, `wgl`, or `webgl`.
[Platforms](#platforms) lists the backends and providers for each platform.

### Build against a prefix

Download `maplibre-native-c-<preset>.tar.gz` and unpack it. The archive root is
the install prefix.

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
cc -std=c23 main.c $(pkg-config --cflags --libs maplibre-native-c) -o main
```

On Windows, add `<prefix>/bin` to `PATH` or copy `maplibre-native-c.dll` beside
the executable. Linux and macOS executables find the library through the rpath
that pkg-config adds.

Linux prefixes also carry a complete static archive. A static musl executable
can link it for the non-rendering APIs, but rendering loads EGL or Vulkan
drivers at run time and needs a dynamic loader.

### Add the XCFramework to an Apple app

`MaplibreNativeC.xcframework.zip` holds the framework `MaplibreNativeC` for
every Apple Metal preset. Add it to a Swift package as a binary target, with the
zip's checksum from `SHA256SUMS`.

```swift title="Package.swift"
.binaryTarget(
  name: "MaplibreNativeC",
  url: "https://github.com/maplibre/maplibre-native-ffi/releases/download/<tag>/MaplibreNativeC.xcframework.zip",
  checksum: "<checksum>"
)
```

Swift imports the module `MaplibreNativeC`, and C includes
`<MaplibreNativeC/maplibre_native_c.h>`. The plugin header is the submodule
`MaplibreNativeC.Plugin`.

## Bindings

Each binding wraps the C library in one language. Most carry or download the C
library, and the sections that need an installed prefix say so.

### Kotlin

Add Maven Central, the binding, and the runtime for your backend. The runtime
carries the native library for every ABI.

```kotlin title="build.gradle.kts"
repositories {
  mavenCentral()
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi:{{version}}")
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:{{version}}")
}
```

Take one runtime module:

- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-opengl`
- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-metal`
- `org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan`

On Android, initialize platform services before you create a runtime, as
[Android](#android) describes.

For the snapshot channel, add the Maven snapshot repository and take the
snapshot version of both modules. The runtime modules and Android
initialization match the release.

```kotlin title="build.gradle.kts"
repositories {
  maven("https://central.sonatype.com/repository/maven-snapshots/") {
    content { includeGroup("org.maplibre.nativeffi") }
  }
  mavenCentral()
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi:0.1.0-SNAPSHOT")
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:0.1.0-SNAPSHOT")
}
```

### .NET

Add the binding and the runtime for your backend from
[NuGet](https://www.nuget.org/packages/Maplibre.NativeFfi). The runtime carries
the native library for each Linux, macOS, Windows, and Android runtime
identifier that its backend runs on.

```bash frame="terminal"
dotnet add package Maplibre.NativeFfi
dotnet add package Maplibre.NativeFfi.Runtime.Vulkan
```

Take one runtime package:

- `Maplibre.NativeFfi.Runtime.OpenGL`
- `Maplibre.NativeFfi.Runtime.Metal`
- `Maplibre.NativeFfi.Runtime.Vulkan`

For the snapshot channel, download the packages from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
into a directory, and add that directory as a package source.

```bash frame="terminal"
gh release download unstable-native-snapshot --repo maplibre/maplibre-native-ffi --pattern '*.nupkg' --dir packages
```

```xml title="nuget.config"
<configuration>
  <packageSources>
    <add key="maplibre-snapshot" value="packages" />
  </packageSources>
</configuration>
```

A snapshot's version is the next release's version with a `-dev` suffix, so
take the newest prerelease of both packages.

```bash frame="terminal"
dotnet add package Maplibre.NativeFfi --prerelease
dotnet add package Maplibre.NativeFfi.Runtime.Vulkan --prerelease
```

### Dart

Add the package from [pub.dev](https://pub.dev/packages/maplibre_native_ffi).

```bash
dart pub add maplibre_native_ffi
```

The package downloads the C library for each target when it builds. Releases
include macOS for arm64 alone.

To build against your own copy of the [C library](#build-against-a-prefix),
name it in your application's pubspec. Name an install prefix, or a build
directory that holds `<preset>/install` for each target. A relative path
resolves against the pubspec. A Git dependency on the package needs a local
build.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      local_build: ../maplibre-native-ffi/build
```

For the snapshot channel, depend on the package from Git at `main`. Download
`maplibre-native-c-<preset>.tar.gz` for your target from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot),
unpack it beside the pubspec, and name the unpacked prefix in `local_build`.

```bash frame="terminal"
curl -L https://github.com/maplibre/maplibre-native-ffi/releases/download/unstable-native-snapshot/maplibre-native-c-macos-arm64-metal.tar.gz | tar -xz
```

```yaml title="pubspec.yaml"
dependencies:
  maplibre_native_ffi:
    git:
      url: https://github.com/maplibre/maplibre-native-ffi
      path: bindings/dart
      ref: main

hooks:
  user_defines:
    maplibre_native_ffi:
      local_build: maplibre-native-c-macos-arm64-metal
```

The snapshot rebuilds `main` once a day. If `main` has moved past it, set `ref`
to the commit that the release names.

Each target uses Metal on Apple platforms, OpenGL on Android, and Vulkan
elsewhere. Map an OS to a different backend in `backend`.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      backend:
        android: vulkan
```

The backends are `opengl`, `metal`, and `vulkan`. The keys are `android`,
`ios`, `linux`, `macos`, and `windows`.

To download through a mirror, name its base URL in `release_url`. The mirror
serves each release tag as a directory that holds that release's archives.

```yaml title="pubspec.yaml"
hooks:
  user_defines:
    maplibre_native_ffi:
      release_url: https://mirror.internal/maplibre-native-ffi
```

### Go

Add the module at the release's version.

```bash frame="terminal"
go get github.com/maplibre/maplibre-native-ffi/bindings/go@v{{version}}
```

cgo finds the C library through pkg-config. Unpack the release's

```bash frame="terminal"
export PKG_CONFIG_PATH=<prefix>/share/pkgconfig
```

For the snapshot channel, take the module from `main` and the C library from the

### Python

Install the binding and the runtime for your backend from
[PyPI](https://pypi.org/project/maplibre-native-ffi/). The runtime holds the
binding's native extension, with the C library linked in.

```bash frame="terminal"
pip install maplibre-native-ffi maplibre-native-ffi-runtime-vulkan
```

Take one runtime distribution. Importing `maplibre_native_ffi` raises
`ImportError` unless exactly one is installed.

- `maplibre-native-ffi-runtime-opengl`
- `maplibre-native-ffi-runtime-metal`
- `maplibre-native-ffi-runtime-vulkan`

The wheels serve Python 3.14 and later. The OpenGL and Vulkan runtimes serve
Linux with glibc and Windows, for x64 and arm64, and macOS 14.3 and later for
arm64. The Metal runtime serves macOS alone. To choose the runtime by platform,
add an environment marker to each:

```toml title="pyproject.toml"
[project]
dependencies = [
  "maplibre-native-ffi",
  "maplibre-native-ffi-runtime-metal; sys_platform == 'darwin'",
  "maplibre-native-ffi-runtime-opengl; sys_platform != 'darwin'",
]
```

For the snapshot channel, install both distributions from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot).
A snapshot's version is a development release of the next release, so pip
takes it only with `--pre`.

```bash frame="terminal"
pip install --pre maplibre-native-ffi maplibre-native-ffi-runtime-vulkan --find-links https://github.com/maplibre/maplibre-native-ffi/releases/expanded_assets/unstable-native-snapshot
```

With uv, name the snapshot release as a flat index for both distributions:

```toml title="pyproject.toml"
[project]
dependencies = ["maplibre-native-ffi", "maplibre-native-ffi-runtime-vulkan"]

[[tool.uv.index]]
name = "maplibre-snapshots"
url = "https://github.com/maplibre/maplibre-native-ffi/releases/expanded_assets/unstable-native-snapshot"
format = "flat"
explicit = true

[tool.uv.sources]
maplibre-native-ffi = { index = "maplibre-snapshots" }
maplibre-native-ffi-runtime-vulkan = { index = "maplibre-snapshots" }
```

The snapshot release holds only the latest wheels, so a lockfile that names an
older snapshot fails to install once the snapshot moves on.

### Rust

Add the crate from [crates.io](https://crates.io/crates/maplibre-native-ffi).

```bash frame="terminal"
cargo add maplibre-native-ffi
```

The build script downloads the C library for the target. Releases include macOS
for arm64 alone, and the published crates do not support Emscripten.

Each target uses Metal on Apple platforms, OpenGL on Android and OpenHarmony,
and Vulkan elsewhere. Enable one backend feature, `opengl`, `metal`, or
`vulkan`, to choose another. A feature on a target-specific dependency applies
to that target alone.

```toml title="Cargo.toml"
[dependencies]
maplibre-native-ffi = "{{version}}"

[target.'cfg(target_os = "android")'.dependencies]
maplibre-native-ffi = { version = "{{version}}", features = ["vulkan"] }
```

To build against your own copy of the [C library](#build-against-a-prefix), set
`MAPLIBRE_NATIVE_FFI_LOCAL_BUILD` to an absolute path. Name an install prefix,
or a build directory that holds `<preset>/install` for each target. A Git or
path dependency on the crate needs a local build.

```toml title=".cargo/config.toml"
[env]
MAPLIBRE_NATIVE_FFI_LOCAL_BUILD = { value = "../maplibre-native-ffi/build", relative = true }
```

For the snapshot channel, depend on the crate from Git at `main`. Cargo also
fetches the repository's submodules, which takes a while the first time.
Download `maplibre-native-c-<preset>.tar.gz` for your target from the
[snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot),
unpack it in the workspace, and name the unpacked prefix in
`MAPLIBRE_NATIVE_FFI_LOCAL_BUILD`.

```bash frame="terminal"
curl -L https://github.com/maplibre/maplibre-native-ffi/releases/download/unstable-native-snapshot/maplibre-native-c-linux-gnu-x64-vulkan.tar.gz | tar -xz
```

```toml title="Cargo.toml"
[dependencies]
maplibre-native-ffi = { git = "https://github.com/maplibre/maplibre-native-ffi", branch = "main" }
```

```toml title=".cargo/config.toml"
[env]
MAPLIBRE_NATIVE_FFI_LOCAL_BUILD = { value = "maplibre-native-c-linux-gnu-x64-vulkan", relative = true }
```

The snapshot rebuilds `main` once a day. If `main` has moved past it, replace
`branch` with a `rev` set to the commit that the release names.

To download through a mirror, set `MAPLIBRE_NATIVE_FFI_RELEASE_URL` to its base
URL. The mirror serves each release tag as a directory that holds that
release's archives.

### TypeScript

Add the package from [npm](https://www.npmjs.com/package/@maplibre/native-ffi)
with exactly one backend package: `@maplibre/native-ffi-opengl`,
`@maplibre/native-ffi-metal`, or `@maplibre/native-ffi-vulkan`.

```bash frame="terminal"
npm install @maplibre/native-ffi @maplibre/native-ffi-vulkan
```

The backend package installs the C library for the host. The binding runs on
Node.js 24.11, Bun 1.4.3, Deno 2.9.7, and later, on Linux with glibc and on
macOS. Releases include macOS for arm64 alone. Deno imports the package as
`npm:@maplibre/native-ffi` and needs `--allow-ffi --allow-read --allow-env`.

npm has no snapshot channel. To try `main`, pack the packages for your preset
in a checkout of this repository, then install the tarballs:

```bash frame="terminal"
mise run //bindings/typescript:pack linux-gnu-x64-vulkan
npm install path/to/maplibre-native-ffi/bindings/typescript/build/npm/*.tgz
```

On OpenHarmony, build the library with
`mise -E ohos run //bindings/typescript:build <preset>`, ship it with the SDK's
`libc++_shared.so` in the application's `libs/<abi>` directory, and bundle
`bindings/typescript/src/arkts.ts`.

### Zig

Add the package from a release. The Zig binding does not support iOS, tvOS, or
Emscripten.

```bash frame="terminal"
zig fetch --save https://github.com/maplibre/maplibre-native-ffi/releases/download/v{{version}}/maplibre-native-ffi-zig.tar.gz
```

```zig title="build.zig"
const maplibre = b.dependency("maplibre_native_ffi", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("maplibre_native_ffi", maplibre.module("maplibre_native_ffi"));
```

The build downloads the C library for the target. Releases include macOS for
arm64 alone, so an Intel Mac targets `aarch64-macos` or uses a local build. Each
target uses Metal on
macOS, OpenGL on Android and OpenHarmony, and Vulkan elsewhere. Pass `.backend`
as `.opengl`, `.metal`, or `.vulkan` to choose another. Windows needs the `msvc`
ABI, which Zig doesn't choose by default, so build with
`-Dtarget=x86_64-windows-msvc` or `-Dtarget=aarch64-windows-msvc`.

On Linux, macOS, Android, and OpenHarmony, an executable that `zig build run`
runs finds the library in Zig's package directory. An installed executable finds
it beside itself on Windows and in `../lib` elsewhere, so install it from the
package's `prefix`, and on Windows run the installed executable:

```zig title="build.zig"
const library = switch (target.result.os.tag) {
    .windows => "bin/maplibre-native-c.dll",
    .macos => "lib/libmaplibre-native-c.dylib",
    else => "lib/libmaplibre-native-c.so",
};
const prefix = maplibre.namedLazyPath("prefix");
b.getInstallStep().dependOn(&b.addInstallFile(prefix.path(b, library), library).step);
```

Zig has no libc for Android or OpenHarmony, so a build for either uses its SDK's.
Pass the dependency `.@"system-root"` as the sysroot directory, the NDK's
`sysroot` or the OpenHarmony SDK's `native/sysroot`, and `.@"target-libc"` as a
libc file in the format that `zig libc` prints. The file names `usr/include` and
its target subdirectory as the include directories, and the target's CRT
directory as both `crt_dir` and `cc_dir`: `usr/lib/<target>/<API level>` in the
NDK, `usr/lib/<target>` in the OpenHarmony SDK. Call `setLibCFile` with the same
file on each artifact that imports the module. An app ships
`libmaplibre-native-c.so` in its `lib/<abi>` directory.

The [snapshot release](https://github.com/maplibre/maplibre-native-ffi/releases/tag/unstable-native-snapshot)
publishes the same package from `main`. Run the same `zig fetch --save` again
to move to the latest snapshot.

```bash frame="terminal"
zig fetch --save https://github.com/maplibre/maplibre-native-ffi/releases/download/unstable-native-snapshot/maplibre-native-ffi-zig.tar.gz
```

To build against your own copy of the [C library](#build-against-a-prefix),
pass the dependency a `local-build` path. Name an install prefix, or a build
directory that holds `<preset>/install` for each target. A path from the command
line must be absolute. A Git dependency on the repository needs a local build.

```zig title="build.zig"
const maplibre = b.dependency("maplibre_native_ffi", .{
    .target = target,
    .optimize = optimize,
    .@"local-build" = b.option(std.Build.LazyPath, "local-build", "MapLibre Native C library build"),
});
```

## Platforms

### Linux

Linux runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

### macOS

macOS runs the Metal, Vulkan, and OpenGL backends, with EGL as the OpenGL
context provider. Apple provides neither Vulkan
nor EGL, so a host that chooses one of those backends loads
[MoltenVK](https://github.com/KhronosGroup/MoltenVK) or
[ANGLE](https://chromium.googlesource.com/angle/angle) itself.

### Windows

Windows runs the Vulkan and OpenGL backends, with WGL as the OpenGL context
provider.

### Android

Android runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

An Android app using Kotlin/JVM depends on a Kotlin runtime AAR, which carries
the native library for every ABI.

```kotlin title="build.gradle.kts"
implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-vulkan:{{version}}")
```

A Kotlin/Native target gets the native library from its runtime KLIB, and the
app packages nothing else for it.

An app's native code, built with CMake or ndk-build, links the runtime AAR's
library through [Prefab](https://developer.android.com/build/native-dependencies).
The app can use any `ANDROID_STL`.

```kotlin title="build.gradle.kts"
android {
  buildFeatures {
    prefab = true
  }
}

dependencies {
  implementation("org.maplibre.nativeffi:maplibre-native-ffi-runtime-opengl-android:{{version}}")
}
```

```cmake title="CMakeLists.txt"
find_package(maplibre-native-c REQUIRED CONFIG)
target_link_libraries(app PRIVATE maplibre-native-c::maplibre-native-c)
```

Android platform initialization is required once per process, before creating
a runtime. Pass an `android.content.Context`; every binding exposes this call
under its own name.

### iOS

iOS runs the Metal backend, on the device, in the simulator, and under Mac
Catalyst. A Mac Catalyst app links the Mac Catalyst library in place of the
macOS library.

### OpenHarmony

OpenHarmony runs the Vulkan and OpenGL backends, with EGL as the OpenGL context
provider.

### Web

Emscripten runs the WebGPU and OpenGL backends, with WebGL as the OpenGL context
provider.

A page that loads a browser module must be cross-origin isolated: serve it with
the `Cross-Origin-Opener-Policy: same-origin` and
`Cross-Origin-Embedder-Policy: require-corp` headers. The module reserves a
fixed 512 MB heap.
