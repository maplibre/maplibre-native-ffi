Every integration performs the same operations: create a runtime and a map, load
a style, attach a render session, render frames, and destroy the three in order.
This page shows them once, in a program that keeps a street map on screen.

One thread does all of it. The thread that creates the runtime becomes the
runtime's owner thread, the map that you create under that runtime takes the
same owner thread, and attaching the render session on that thread makes it the
session's owner thread as well.

`mln_map_set_style_url` returns once the map accepts the request, and the style
document, its sources, and its tiles arrive across the pumps that follow. When
a style fails to load, the runtime reports a map loading-failed event whose
message carries the failure text.

Each pump call does the work that the map has queued: parsing style documents,
delivering network responses, and advancing camera transitions.

The map publishes render updates, and the render session draws them.
`mln_render_session_render_update` renders the map's latest update, presents it
through the surface, and reports whether it rendered. On the first turns of
the loop the map has usually published no update for the session's extent yet,
so the call reports no render and the program keeps its request pending.

Teardown reverses creation. `mln_map_destroy` reports
`MLN_STATUS_INVALID_STATE` while a render session is attached, and
`mln_runtime_destroy` reports the same status while the runtime owns live maps.

Run the program. The window shows a street map of San Francisco at zoom 13, and
more detail appears as tiles arrive. For the model behind the three objects
that you created, read [Concepts](/maplibre-native-ffi/concepts/).
