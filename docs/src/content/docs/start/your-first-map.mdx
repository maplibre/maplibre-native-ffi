Every integration performs the same operations: create a runtime and a map, load
a style, attach a render session, render frames, and destroy the three in order.
This page shows them once, in a program that keeps a street map on screen.

One thread does all of it. The thread that creates the runtime becomes the
runtime's owner thread, the map that you create under that runtime takes the
same owner thread, and attaching the render session on that thread makes it the
session's owner thread as well.

<Code code={region(firstMap, "create")} lang="c" title="first-map.c" />

`mln_map_set_style_url` returns once the map accepts the request, and the style
document, its sources, and its tiles arrive across the pumps that follow. When a
style fails to load, the runtime reports a map loading-failed event whose message
carries the failure text.

Each pump call does the work that the map has queued: parsing style documents,
delivering network responses, and advancing camera transitions. The map publishes
render updates as that work lands, and the render session draws them.

<Code code={region(firstMap, "render")} lang="c" title="first-map.c" />

Teardown reverses creation. `mln_map_destroy` reports `MLN_STATUS_INVALID_STATE`
while a render session is attached, and `mln_runtime_destroy` reports the same
status while the runtime owns live maps.

more detail appears as tiles arrive. For the model behind the three objects that
